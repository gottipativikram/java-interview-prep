Java 8, Streams, Optional, Lambdas & Coding Problems

B1 Explain Java 8 features. TCS

Java 8 added lambdas, functional interfaces (java.util.function), method references, the Stream API, Optional, default and static methods in interfaces, the new Date/Time API (java.time), CompletableFuture, Collectors, forEach/removeIf/computeIfAbsent on collections, StringJoiner, and Nashorn. Together they let you write Java in a declarative, functional style. (Section A covers each one in more detail.)

Java 8 (March 2014) was the largest language change since generics. It brought functional programming into Java and modernised several core APIs.

Small demo touching several features:

import java.time.*;
import java.time.format.DateTimeFormatter;
import java.util.*;
import java.util.concurrent.CompletableFuture;
import java.util.stream.Collectors;

public class Java8Tour {
    interface Greeter {
        String name();
        default String greet() { return "Hello, " + name(); }   // default method
        static Greeter of(String n) { return () -> n; }           // static method + lambda
    }

    public static void main(String[] args) throws Exception {
        // Lambdas + streams + method references
        List<String> langs = List.of("java", "kotlin", "scala", "go");
        String joined = langs.stream()
                .filter(s -> s.length() > 2)
                .map(String::toUpperCase)
                .collect(Collectors.joining(", ", "[", "]"));
        System.out.println(joined);                               // [JAVA, KOTLIN, SCALA]

        // Optional
        Optional<String> first = langs.stream().filter(s -> s.startsWith("k")).findFirst();
        System.out.println(first.orElse("none"));                 // kotlin

        // Default/static interface methods
        System.out.println(Greeter.of("Nagesh").greet());         // Hello, Nagesh

        // java.time
        LocalDate d = LocalDate.of(2024, 2, 28).plusDays(1);
        System.out.println(d + " " + d.format(DateTimeFormatter.ofPattern("dd-MMM-yyyy"))); // 2024-02-29 29-Feb-2024
        System.out.println(Duration.ofMinutes(135));              // PT2H15M

        // CompletableFuture
        CompletableFuture<Integer> f = CompletableFuture.supplyAsync(() -> 20)
                .thenApply(x -> x * 2)
                .thenCombine(CompletableFuture.supplyAsync(() -> 2), Integer::sum);
        System.out.println(f.get());                              // 42

        // StringJoiner
        StringJoiner sj = new StringJoiner("|", "<", ">");
        sj.add("a").add("b");
        System.out.println(sj);                                   // <a|b>
    }
}

Gotchas worth mentioning:

  • A default method conflict (class implements two interfaces with the same default) is a compile error; you must override and may call A.super.method().
  • Class methods always beat interface defaults ("class wins" rule).
  • Metaspace is unbounded by default: a classloader leak (e.g. redeploying in Tomcat) now eats native memory instead of failing fast, so set MaxMetaspaceSize in production.
  • java.time types are immutable: date.plusDays(1) returns a new object, so calling it without assigning the result does nothing.

Likely follow-ups:

  • Why were default methods introduced? So that interfaces like Collection could get stream()/forEach() without breaking every existing implementation.
  • Difference between LocalDateTime and ZonedDateTime/Instant? LocalDateTime has no zone; ZonedDateTime adds a zone with DST rules; Instant is a UTC point on the timeline (use it for storage and timestamps).
  • What replaced Nashorn? Nothing in the JDK. Use GraalJS (GraalVM polyglot) or the standalone Nashorn library.
  • What happens to PermGen flags on Java 8? -XX:PermSize/MaxPermSize are ignored with a warning.
B2 What is a lambda expression?

A lambda is an anonymous function, (params) -> body, that provides the implementation of a functional interface's single abstract method. It replaces boilerplate anonymous inner classes. It can only capture local variables that are effectively final. Unlike an anonymous class, this inside a lambda refers to the enclosing instance.

Comparator<String> byLen = (a, b) -> Integer.compare(a.length(), b.length());
Runnable r = () -> System.out.println("run");

A lambda is an anonymous function: a block of code with parameters and a body, but no name and no class of its own. It can be used anywhere a functional interface is expected. The compiler infers which interface from the context (the target type).

Syntax forms:

Runnable r          = () -> System.out.println("no args");          // no params
Consumer<String> c  = s -> System.out.println(s);                    // one param, parens optional
BinaryOperator<Integer> add = (a, b) -> a + b;                       // multiple params, expression body
Comparator<String> cmp = (String a, String b) -> a.compareTo(b);     // explicit types
BiFunction<Integer,Integer,Integer> f = (var a, var b) -> a * b;     // Java 11: var (allows annotations)
Function<Integer,Integer> sq = x -> {                                // block body: needs return
    int y = x * x;
    return y;
};

Effectively-final capture: A lambda can read local variables from the enclosing scope only if they are final or effectively final (never reassigned after initialisation).

int base = 10;
Function<Integer,Integer> addBase = x -> x + base;  // OK
// base = 20;   // compile error: variable used in lambda must be final or effectively final

Why? Locals live on the stack frame, which may be gone by the time the lambda runs (for example on another thread). Java copies the value into the lambda, and the effectively-final rule keeps that copy correct and avoids data races. Instance fields and static fields can be modified, because the lambda captures this rather than a copy of the field.

Workaround (usually a smell): int[] counter = {0}; list.forEach(x -> counter[0]++);. Prefer count(), AtomicInteger, or a reduction.

public class ThisDemo {
    String name = "outer";
    void run() {
        Runnable lambda = () -> System.out.println(this.name);       // prints "outer"
        Runnable anon = new Runnable() {
            String name = "inner";
            public void run() { System.out.println(this.name); }      // prints "inner"
        };
        lambda.run(); anon.run();
    }
    public static void main(String[] a) { new ThisDemo().run(); }
}

How lambdas work internally (invokedynamic):

  1. javac moves the lambda body into a private synthetic method, e.g. private static lambda$main$0(String). If it uses this, the method is an instance method.
  2. At the creation site, javac emits an invokedynamic instruction whose bootstrap method is LambdaMetafactory.metafactory.
  3. The first time the instruction runs, the bootstrap method creates (with a hidden class) an implementation of the functional interface that delegates to the synthetic method. It returns a CallSite, which is then linked permanently.
  4. Later executions reuse the linked call site. Non-capturing lambdas return the same instance each time; capturing lambdas create a new instance holding the captured values.

Benefits: no class-file bloat, and the JVM can change the strategy later without recompiling. You can see this with javap -c -p MyClass.

Gotchas:

  • Checked exceptions: Function.apply declares none, so a lambda that calls Files.readString must catch the exception or wrap it.
  • Do not rely on lambda identity (==) or serialisation unless the target interface is Serializable.
  • Overload ambiguity: submit(() -> foo()) can match both Runnable and Callable. Javac picks Callable if foo() returns a value.

Likely follow-ups:

  • Can a lambda throw a checked exception? Only if the functional interface's method declares it (for example Callable.call() throws Exception). Otherwise wrap it or write a custom ThrowingFunction.
  • Is a lambda an object? Yes. At runtime it is an instance of a hidden class implementing the interface.
  • Can lambdas have generic type parameters? No. Use a method reference or a generic interface method instead.
  • Why is "effectively final" a rule and not just "final"? It is convenience: Java 8 removed the need to write the final keyword, but the semantics are the same.
B3 Functional interfaces with respect to lambdas. TCS

A functional interface has exactly one abstract method (@FunctionalInterface is optional and makes the compiler enforce it). A lambda is an instance of one.

A functional interface has exactly one abstract method (SAM, single abstract method). It may have any number of default/static methods, and methods inherited from Object (equals, toString) do not count. @FunctionalInterface is optional, but it makes the compiler enforce the rule.

@FunctionalInterface
interface Validator<T> {
    boolean validate(T t);
    default Validator<T> and(Validator<T> other) { return t -> validate(t) && other.validate(t); }
    boolean equals(Object o);   // allowed: Object method
}

Composition:

import java.util.function.*;

public class Composition {
    public static void main(String[] args) {
        Function<Integer,Integer> times2 = x -> x * 2;
        Function<Integer,Integer> plus3  = x -> x + 3;

        System.out.println(times2.andThen(plus3).apply(5));  // (5*2)+3 = 13  -> this first, then arg
        System.out.println(times2.compose(plus3).apply(5));  // (5+3)*2 = 16  -> arg first, then this
        System.out.println(Function.<Integer>identity().apply(7)); // 7

        Predicate<String> notEmpty = s -> !s.isEmpty();
        Predicate<String> shortStr = s -> s.length() < 5;
        System.out.println(notEmpty.and(shortStr).test("abc"));   // true
        System.out.println(notEmpty.and(shortStr).negate().test("abc")); // false
        System.out.println(shortStr.or(s -> s.startsWith("x")).test("xylophone")); // true
        System.out.println(Predicate.not(String::isBlank).test("  ")); // false (Java 11)
        System.out.println(Predicate.isEqual("a").test("a"));    // true

        Consumer<StringBuilder> a = sb -> sb.append("A");
        Consumer<StringBuilder> b = sb -> sb.append("B");
        StringBuilder sb = new StringBuilder();
        a.andThen(b).accept(sb);
        System.out.println(sb);                                   // AB

        BinaryOperator<Integer> max = BinaryOperator.maxBy(Integer::compare);
        System.out.println(max.apply(3, 9));                      // 9

        IntUnaryOperator inc = x -> x + 1;
        System.out.println(inc.andThen(x -> x * 10).applyAsInt(1)); // 20
    }
}

Gotchas:

  • andThen vs compose is a common trick question. f.andThen(g) is g(f(x)); f.compose(g) is f(g(x)).
  • Predicate.and short-circuits like &&.
  • Supplier is not Callable: Supplier.get() cannot throw checked exceptions.
  • Generic interfaces work only with reference types, so Function<int,int> is invalid. Use IntUnaryOperator.

Likely follow-ups:

  • Is Comparator a functional interface even though it declares equals? Yes. equals is an Object method and does not count.
  • Can a functional interface extend another? Yes, as long as the total number of abstract methods stays one.
  • Why so many primitive variants? To avoid boxing cost. There are only int/long/double variants, which is why there is no CharStream.
  • Is @FunctionalInterface mandatory? No. It is a compile-time check and documentation.
B4 What is a method reference? (4 kinds) Co. 2

A method reference is shorthand for a lambda that only calls an existing method.

  1. Static method: Integer::parseInt (s -> Integer.parseInt(s))
  2. Instance method of a particular object: System.out::println
  3. Instance method of an arbitrary object of a type: String::toUpperCase (s -> s.toUpperCase())
  4. Constructor: ArrayList::new

A method reference is shorthand for a lambda whose body only calls an existing method. Syntax: Target::method.

# Kind Syntax Lambda equivalent Example
1 Static method ClassName::staticMethod x -> ClassName.staticMethod(x) Integer::parseInt
2 Instance method of a particular (bound) object instance::method x -> instance.method(x) System.out::println, "Hi"::concat
3 Instance method of an arbitrary object of a type (unbound) ClassName::instanceMethod (obj, args) -> obj.method(args) String::toUpperCase, String::compareToIgnoreCase
4 Constructor ClassName::new / Type[]::new args -> new ClassName(args) ArrayList::new, int[]::new 
import java.util.*;
import java.util.function.*;
import java.util.stream.*;

public class MethodRefs {
    record Person(String name) {}

    static boolean isLong(String s) { return s.length() > 4; }

    public static void main(String[] args) {
        List<String> words = List.of("apple", "Kiwi", "banana", "fig");

        // 1. Static
        Function<String,Integer> parse = Integer::parseInt;
        System.out.println(parse.apply("42"));                          // 42
        System.out.println(words.stream().filter(MethodRefs::isLong).toList()); // [apple, banana]

        // 2. Bound instance (the receiver is fixed)
        String prefix = "Mr. ";
        Function<String,String> addPrefix = prefix::concat;
        System.out.println(addPrefix.apply("Bean"));                    // Mr. Bean
        words.forEach(System.out::println);                             // System.out is the bound object

        // 3. Unbound instance (the first parameter becomes the receiver)
        Function<String,String> upper = String::toUpperCase;            // s -> s.toUpperCase()
        BiFunction<String,String,Boolean> eq = String::equalsIgnoreCase; // (a,b) -> a.equalsIgnoreCase(b)
        System.out.println(upper.apply("x") + " " + eq.apply("A", "a"));// X true
        List<String> sorted = new ArrayList<>(words);
        sorted.sort(String::compareToIgnoreCase);
        System.out.println(sorted);                                     // [apple, banana, fig, Kiwi]

        // 4. Constructor
        Supplier<List<String>> listMaker = ArrayList::new;
        Function<String,Person> mk = Person::new;
        IntFunction<String[]> arr = String[]::new;
        System.out.println(listMaker.get() + " " + mk.apply("Ana"));    // [] Person[name=Ana]
        String[] asArray = words.stream().toArray(String[]::new);
        System.out.println(asArray.length + " " + arr.apply(3).length); // 4 3
        Set<String> set = words.stream().collect(Collectors.toCollection(TreeSet::new));
        System.out.println(set);                                        // [Kiwi, apple, banana, fig]
    }
}

Gotchas:

  • Bound receivers are evaluated eagerly. With obj::method, obj is evaluated when the reference is created. If obj is null you get an NPE immediately, while the equivalent lambda would throw only when called.
  • Ambiguity: Integer::toString can match both static toString(int) and instance toString() for Function<Integer,String>, which is a compile error.
  • Which constructor ::new picks depends on the functional interface's parameter list (Supplier gives no-arg, Function gives one-arg).

Likely follow-ups:

  • When should you prefer a lambda over a method reference? When you need extra logic, argument reordering, or the reference would be ambiguous or less readable.
  • How does String::compareTo fit Comparator<String>? It is unbound: the first argument is the receiver, the second is the parameter.
  • Can you reference super::method? Yes, super::toString inside an instance context.
B5 Stream API methods: intermediate vs terminal. TCSCo. 2Other rounds (Question List)
  • Intermediate operations are lazy and return a Stream: filter, map, flatMap, distinct, sorted, peek, limit, skip, mapToInt/Obj, boxed, takeWhile, dropWhile.
  • Terminal operations trigger execution and close the stream: forEach, collect, reduce, count, min, max, findFirst, findAny, anyMatch, allMatch, noneMatch, toArray, toList (16+).
  • Laziness: nothing runs until a terminal operation is called. Elements then flow through the pipeline one at a time (vertical processing).
  • Short-circuiting operations can stop early: limit, findFirst, findAny, anyMatch, allMatch, noneMatch, takeWhile. These make infinite streams usable.

A stream pipeline = source -> zero or more intermediate operations -> exactly one terminal operation.

Intermediate operations return a new Stream and are lazy: nothing runs until a terminal operation is called.

* = stateful (must remember previously seen elements, or for sorted buffer everything). The others are stateless: each element is processed independently.

Short-circuiting operations can finish without consuming the whole (even infinite) source: limit, takeWhile (intermediate); anyMatch, allMatch, noneMatch, findFirst, findAny (terminal).

Laziness and vertical execution. Elements flow through the pipeline one at a time ("vertically"), not stage by stage:

import java.util.*;
import java.util.stream.*;

public class Laziness {
    public static void main(String[] args) {
        Stream<String> s = Stream.of("a", "bb", "ccc", "dddd")
                .filter(x -> { System.out.println("filter " + x); return x.length() > 1; })
                .map(x -> { System.out.println("map " + x); return x.toUpperCase(); });
        System.out.println("nothing printed yet");          // laziness
        System.out.println(s.findFirst().get());

        // Infinite stream made safe by short-circuiting
        System.out.println(Stream.iterate(1, x -> x * 2).limit(5).toList()); // [1, 2, 4, 8, 16]

        // Reuse is illegal
        Stream<Integer> once = Stream.of(1, 2, 3);
        once.count();
        try { once.count(); }
        catch (IllegalStateException e) { System.out.println(e.getMessage()); }
    }
}

Output:

nothing printed yet
filter a
filter bb
map bb
BB
[1, 2, 4, 8, 16]
stream has already been operated upon or closed

Notice that ccc and dddd were never touched, because findFirst short-circuited.

A stream cannot be reused. It is a one-shot view over the source. If you need it again, use a Supplier<Stream<T>> sup = () -> list.stream(); and call sup.get() each time.

Other important facts:

  • Streams do not store data and should not modify their source. Changing a non-concurrent source during the pipeline causes ConcurrentModificationException or undefined behaviour.
  • Operation order matters for performance: put filter before map and before sorted.
  • sorted is a barrier: it must consume all input before it emits anything, so it breaks the one-element-at-a-time flow.
  • Streams are AutoCloseable. Close streams backed by I/O (Files.lines); collection streams need no closing.
  • Stream.toList() (16) returns an unmodifiable list. Collectors.toList() makes no guarantee, but in practice returns an ArrayList.

Likely follow-ups:

  • What if there is no terminal operation? Nothing executes at all.
  • Difference between findFirst and findAny? findAny may return any element and is cheaper in parallel; findFirst respects encounter order.
  • forEach vs forEachOrdered? In parallel, forEach does not guarantee order; forEachOrdered does, at a cost to performance.
  • takeWhile vs filter? takeWhile stops at the first element that fails; filter checks every element.
B6 map() vs flatMap() TCSHexaware

map is a one-to-one transform (Stream<T> → Stream<R>). flatMap is one-to-many: each element maps to a Stream, and those streams are flattened into one (Stream<List<T>> → Stream<T>).

List<String> words = List.of("hi", "yo");
words.stream().map(String::length).toList();                         // [2, 2]
words.stream().flatMap(w -> w.chars().mapToObj(c -> (char) c)).toList(); // [h, i, y, o]
  • map(Function<T,R>) is a one-to-one transformation: each input element produces exactly one output element. Stream<T> -> Stream<R>.
  • flatMap(Function<T, Stream<R>>) is one-to-many plus flatten: each element becomes a stream of zero or more elements, and all those streams are concatenated into one. Stream<T> -> Stream<R>, not Stream<Stream<R>>.

If you use map with a function that returns a stream or list, you get nested structure: Stream<List<String>>. flatMap removes one level of nesting.

import java.util.*;
import java.util.stream.*;

public class MapVsFlatMap {
    record Order(String id, List<String> items) {}

    public static void main(String[] args) {
        List<String> sentences = List.of("hello world", "java streams rock");

        // map: one sentence -> one String[]
        List<String[]> arrays = sentences.stream().map(s -> s.split(" ")).toList();
        System.out.println(arrays.size());                                   // 2

        // flatMap: one sentence -> many words, flattened
        List<String> words = sentences.stream()
                .flatMap(s -> Arrays.stream(s.split(" ")))
                .toList();
        System.out.println(words);                                           // [hello, world, java, streams, rock]

        // Real-world: all distinct items across orders
        List<Order> orders = List.of(
                new Order("o1", List.of("pen", "book")),
                new Order("o2", List.of("book", "bag")),
                new Order("o3", List.of()));                                 // 0 elements is fine
        Set<String> items = orders.stream()
                .flatMap(o -> o.items().stream())
                .collect(Collectors.toCollection(TreeSet::new));
        System.out.println(items);                                           // [bag, book, pen]

        // Distinct characters across words
        System.out.println(words.stream()
                .flatMapToInt(String::chars)
                .distinct()
                .mapToObj(c -> String.valueOf((char) c))
                .collect(Collectors.joining()));                             // helowrdjavstmck

        // Optional.flatMap avoids Optional<Optional<T>>
        Optional<String> name = Optional.of(" ana ");
        Optional<String> trimmed = name.flatMap(n -> n.isBlank() ? Optional.empty() : Optional.of(n.trim()));
        System.out.println(trimmed.get());                                   // ana
    }
}

mapMulti (Java 16) is an imperative alternative to flatMap when you produce only a few elements per input. It avoids creating a stream for each element:

Stream.of(1, 2, 3).<Integer>mapMulti((x, sink) -> { if (x % 2 == 1) { sink.accept(x); sink.accept(-x); } })
      .toList(); // [1, -1, 3, -3]

Edge cases: if the flatMap function returns null instead of a stream, it is treated as an empty stream (documented behaviour), but returning Stream.empty() is clearer. A null element inside the list will pass through and can cause NPEs later.

Likely follow-ups:

  • Complexity of flatMap? O(total number of inner elements). It adds the overhead of one stream per outer element.
  • Is flatMap lazy? Yes. Since Java 10 it also short-circuits correctly inside inner streams (before that, flatMap + findFirst consumed the whole inner stream).
  • flatMap on Optional vs on Stream? Same idea: Optional.flatMap flattens Optional<Optional<T>>, and Stream.flatMap flattens Stream<Stream<T>>.
B7 How do you debug a Java Stream? Hexaware

Use peek() to log elements between stages, or break the pipeline into variables and set an IDE breakpoint inside the lambda. IntelliJ's Stream Trace debugger also works. Don't put business logic in peek, because it may not run at all if the terminal operation can skip elements (e.g. count() on a sized stream).

List.of(1, 2, 3, 4).stream()
    .peek(n -> System.out.println("in: " + n))
    .filter(n -> n % 2 == 0)
    .peek(n -> System.out.println("even: " + n))
    .map(n -> n * 10)
    .toList();
// Output: in: 1, in: 2, even: 2, in: 3, in: 4, even: 4  -> [20, 40]

Streams are hard to debug: a single line hides several stages, stack traces are full of ReferencePipeline$... frames, and evaluation is lazy and vertical. Techniques:

1. peek() for logging intermediate values

import java.util.*;

peek caveats (frequently asked):

  • It is lazy. Without a terminal operation, peek never runs.
  • Short-circuiting skips it. With findFirst/anyMatch/limit, peek runs only for the elements actually pulled.
  • count() may skip the whole pipeline (Java 9+). If the size is known from the source and no operation can change it, count() returns the size directly:
    long n = List.of(1, 2, 3).stream().peek(System.out::println).count(); // prints NOTHING, n = 3
long m = List.of(1, 2, 3).stream().filter(x -> true).peek(System.out::println).count(); // prints 1 2 3
  • Its Javadoc says it exists "mainly to support debugging". Do not use it for business side effects such as mutating elements or saving to a DB, because the stream implementation is free to elide it.
  • In parallel streams, peek output is interleaved across threads.

2. Breakpoints inside lambdas. In IntelliJ/Eclipse, a breakpoint on a stream line offers "Line", "Lambda", or "All". Choose a lambda breakpoint to stop inside x -> x * 10 for each element. Conditional breakpoints (x == 8) are very useful here.

3. IntelliJ Stream Trace (Java Stream Debugger). While paused on a line containing a stream chain, click the "Trace Current Stream Chain" button in the Debug tool window. It evaluates the pipeline and shows a tab for each stage, with arrows mapping input elements to output elements (Split mode or Flat mode). This is the quickest way to see where an element got filtered out.

4. Split the pipeline into named variables or methods.

Predicate<Employee> isSenior = e -> e.years() > 5;          // can be unit tested on its own
Function<Employee, String> toLabel = e -> e.name() + "(" + e.dept() + ")";
List<String> labels = emps.stream().filter(isSenior).map(toLabel).toList();

Extracting lambdas into methods (.map(this::toLabel)) also produces meaningful stack-trace frames.

5. Collect intermediate results temporarily: var afterFilter = stream.filter(..).toList(); then inspect it, then continue streaming.

6. Exceptions: read the stack trace from the frame that names your lambda (lambda$main$0). Lambda methods are numbered by order of appearance in the class.

Likely follow-ups:

  • Why does peek print nothing in my code? There is no terminal operation, or count() skipped the pipeline, or a short-circuit stopped early.
  • Can peek modify elements? Technically it can mutate mutable objects, but that is an anti-pattern. Use map.
  • How do you debug a parallel stream? Switch to sequential() temporarily, and log Thread.currentThread().getName() in peek.
B8 Optional for null-safe access; chaining with streams.

Optional<T> is a container that may or may not hold a value. Use it as a return type to force callers to handle the "absent" case, but not for fields or parameters. map transforms the value, flatMap is for functions that return an Optional, and filter, orElse(default) (always evaluated), orElseGet(supplier) (lazy), orElseThrow(), ifPresentOrElse, and Optional.stream() (Java 9; gives 0 or 1 elements) cover the rest.

String city = Optional.ofNullable(user)
        .map(User::getAddress)
        .map(Address::getCity)
        .orElseGet(() -> "UNKNOWN");

List<String> emails = ids.stream()
        .map(repo::findEmail)          // Stream<Optional<String>>
        .flatMap(Optional::stream)     // keep only present values
        .toList();

Optional<T> is a container that holds either a non-null value or nothing. Its purpose is to be a return type that tells callers "this may be absent, handle it", so that NPE risk shows up in the method signature.

Creation: Optional.of(v) (NPE if v is null), Optional.ofNullable(v), Optional.empty().

Null-safe navigation (replaces nested null checks):

import java.util.*;
import java.util.stream.*;

public class OptionalDemo {
    record City(String name) {}
    record Address(City city) {}
    record User(String id, Address address) {}

    static Map<String, User> db = Map.of(
            "u1", new User("u1", new Address(new City("Pune"))),
            "u2", new User("u2", null));

    static Optional<User> findUser(String id) { return Optional.ofNullable(db.get(id)); }

    static String cityOf(String id) {
        return findUser(id)
                .map(User::address)        // returns empty if address is null
                .map(Address::city)
                .map(City::name)
                .map(String::toUpperCase)
                .orElse("UNKNOWN");
    }

    static String expensiveDefault() { System.out.println("computing default..."); return "X"; }

    public static void main(String[] args) {
        System.out.println(cityOf("u1"));   // PUNE
        System.out.println(cityOf("u2"));   // UNKNOWN
        System.out.println(cityOf("u9"));   // UNKNOWN

        // orElse vs orElseGet
        Optional<String> present = Optional.of("A");
        present.orElse(expensiveDefault());          // prints "computing default..." anyway!
        present.orElseGet(OptionalDemo::expensiveDefault); // prints nothing

        // Chaining Optional with Stream: keep only the present values
        List<String> ids = List.of("u1", "u9", "u2");
        List<User> found = ids.stream()
                .map(OptionalDemo::findUser)     // Stream<Optional<User>>
                .flatMap(Optional::stream)       // Java 9+: drops the empties
                .toList();
        System.out.println(found.size());        // 2

        // Java 8 equivalent
        List<User> found8 = ids.stream().map(OptionalDemo::findUser)
                .filter(Optional::isPresent).map(Optional::get).collect(Collectors.toList());
        System.out.println(found8.size());       // 2

        // Stream terminal ops already return Optional
        Optional<String> longest = Stream.of("a", "abc", "ab").max(Comparator.comparingInt(String::length));
        longest.ifPresentOrElse(System.out::println, () -> System.out.println("empty")); // abc

        // Throw a domain exception
        try {
            findUser("u9").orElseThrow(() -> new NoSuchElementException("User u9 not found"));
        } catch (NoSuchElementException e) { System.out.println(e.getMessage()); }
    }
}

Likely follow-ups:

  • Why is Optional not Serializable? It was designed only as a return type, not for fields or DTOs.
  • orElse vs orElseGet? orElse evaluates its argument always; orElseGet calls the supplier only when the Optional is empty.
  • Does Jackson/JPA support Optional? Jackson needs jdk8-module (included by default in Spring Boot). Spring Data repositories return Optional<T> from findById. JPA entity fields should not be Optional.
  • Is Optional.get() deprecated? Not deprecated, but orElseThrow() (Java 10) was added as the clearer name for the same behaviour.
B9 Sequential vs parallel streams.

A sequential stream runs on a single thread. A parallel stream (parallelStream() / .parallel()) splits the work across the common ForkJoinPool (roughly cores − 1 threads). Parallel helps for large, CPU-bound, stateless work on sources that split easily (ArrayList, arrays). It hurts for small data, I/O, LinkedList, or anything order-dependent or synchronized. Lambdas must be stateless and side-effect free. Use forEachOrdered if output order matters. findAny is cheaper than findFirst in parallel.

  • Sequential (default): one thread (the caller's) processes all elements in encounter order.
  • Parallel (list.parallelStream() or stream.parallel()): the source is split into chunks with a Spliterator, the chunks are processed on the ForkJoinPool common pool, and the partial results are combined.

Internals:

  • Common pool: ForkJoinPool.commonPool() has Runtime.availableProcessors() - 1 worker threads, and the calling thread also takes part. Configure it with -Djava.util.concurrent.ForkJoinPool.common.parallelism=N. The pool is shared JVM-wide (with CompletableFuture.supplyAsync without an executor, other parallel streams, and so on), so a blocking task in one place starves everything else.
  • Work stealing: each worker has its own deque, and idle workers steal tasks from the tail of others' deques.
  • Spliterator: trySplit() divides the source. How well it splits decides whether parallel helps:
    • Excellent: ArrayList, arrays, IntStream.range, HashMap/HashSet (reasonably good)
    • Poor: LinkedList, Stream.iterate, BufferedReader.lines(), Stream.generate (sequential by nature)
  • Characteristics: SIZED, SUBSIZED, ORDERED, DISTINCT, SORTED, IMMUTABLE, CONCURRENT, NONNULL let the framework optimise.

Custom pool trick (isolate from the common pool). This relies on an implementation detail: tasks forked from inside a ForkJoinPool run in that pool.

ForkJoinPool pool = new ForkJoinPool(4);
long result = pool.submit(() -> bigList.parallelStream().mapToLong(this::cpuHeavy).sum()).get();
pool.shutdown();

When parallel helps:

  • Large N (Brian Goetz's "NQ model": N x Q, where Q is the cost per element, should be above roughly 10,000)
  • CPU-bound, independent, stateless operations
  • A source that splits well; cheap combine (sum, min); few stateful operations
  • Multiple cores available (do not do this inside a busy web server where each request thread already uses a core)

When it hurts: small collections, I/O or blocking calls (DB, HTTP), LinkedList/iterate sources, boxed streams, order-dependent operations (limit, findFirst, sorted on ordered streams), contention on shared state.

Thread-safety:

import java.util.*;
import java.util.concurrent.*;
import java.util.stream.*;

public class ParallelDemo {
    public static void main(String[] args) {
        // WRONG: shared mutable ArrayList, a race condition
        List<Integer> unsafe = new ArrayList<>();
        try {
            IntStream.range(0, 10_000).parallel().forEach(unsafe::add);
        } catch (ArrayIndexOutOfBoundsException e) { System.out.println("crashed: " + e); }
        System.out.println("unsafe size (often < 10000): " + unsafe.size());

        // RIGHT: let the collector handle the merging
        List<Integer> safe = IntStream.range(0, 10_000).parallel().boxed().toList();
        System.out.println("safe size: " + safe.size());               // 10000, in order

        // Ordering
        IntStream.range(0, 5).parallel().forEach(i -> System.out.print(i + " "));        // e.g. 2 4 3 0 1
        System.out.println();
        IntStream.range(0, 5).parallel().forEachOrdered(i -> System.out.print(i + " ")); // 0 1 2 3 4
        System.out.println();

        // Thread names
        Set<String> threads = ConcurrentHashMap.newKeySet();
        IntStream.range(0, 1000).parallel().forEach(i -> threads.add(Thread.currentThread().getName()));
        System.out.println(threads); // [main, ForkJoinPool.commonPool-worker-1, ...]

        // Non-associative reduce gives a wrong answer in parallel
        int bad = IntStream.rangeClosed(1, 4).parallel().reduce(0, (a, b) -> a - b);
        System.out.println("subtraction reduce (unpredictable): " + bad);
    }
}

Ordering rules: parallel streams preserve encounter order for toList, collect, findFirst, forEachOrdered, limit, skip. That preservation costs buffering. If you do not care about order, use .unordered(), findAny, forEach, or Collectors.toConcurrentMap/groupingByConcurrent.

Requirements for correct parallel reductions: the accumulator and combiner must be associative, non-interfering (do not modify the source), and stateless. The identity must truly be an identity: reduce(10, Integer::sum) adds 10 once per chunk in parallel.

Likely follow-ups:

  • How many threads does a parallel stream use? Common pool parallelism (cores - 1) plus the calling thread.
  • Is parallelStream() on a synchronised list thread-safe? Reading is fine. The real issue is side effects in the lambdas, which you must avoid.
  • Can a parallel stream be slower? Yes. Splitting and merging overhead plus thread hand-offs often make it slower for small or cheap workloads. Benchmark with JMH.
  • How do you turn a parallel stream back to sequential? Call .sequential(). The last mode call wins for the whole pipeline; you cannot have mixed stages.

import java.util.*;
import java.util.function.Function;
import java.util.stream.*;

public class CountDuplicates {

    // Stream version
    static Map<Integer, Long> duplicatesStream(int[] arr) {
        if (arr == null || arr.length == 0) return Map.of();
        return Arrays.stream(arr)
                .boxed()
                .collect(Collectors.groupingBy(Function.identity(), LinkedHashMap::new, Collectors.counting()))
                .entrySet().stream()
                .filter(e -> e.getValue() > 1)
                .collect(Collectors.toMap(Map.Entry::getKey, Map.Entry::getValue,
                        (a, b) -> a, LinkedHashMap::new));
    }

    // Loop version with Map.merge
    static Map<Integer, Integer> duplicatesLoop(int[] arr) {
        Map<Integer, Integer> freq = new LinkedHashMap<>();
        if (arr == null) return freq;
        for (int x : arr) freq.merge(x, 1, Integer::sum);
        freq.values().removeIf(c -> c == 1);
        return freq;
    }

    // Only "how many distinct values are duplicated" using a Set
    static long countDuplicatedValues(int[] arr) {
        Set<Integer> seen = new HashSet<>(), dup = new HashSet<>();
        for (int x : arr) if (!seen.add(x)) dup.add(x);
        return dup.size();
    }

    public static void main(String[] args) {
        int[] arr = {1, 2, 3, 2, 4, 1, 2, 5};
        System.out.println(duplicatesStream(arr));      // {1=2, 2=3}
        System.out.println(duplicatesLoop(arr));        // {1=2, 2=3}
        System.out.println(countDuplicatedValues(arr)); // 2
        System.out.println(duplicatesStream(new int[0]));// {}
        System.out.println(duplicatesLoop(null));       // {}
    }
}

Complexity: O(n) time, O(k) space (k = distinct values). Alternative: sort the array and then count consecutive runs: O(n log n) time, O(1) extra space (if you may mutate the array). For a small bounded range (for example 0..1000), use an int[] count array. Edge cases: null or empty input returns an empty map; all unique values return an empty map; negative numbers work with the map approach but not with a naive count array.

Likely follow-ups:

  • Why LinkedHashMap::new? It keeps first-occurrence order. Plain groupingBy uses HashMap, so the order is unspecified.
  • How do you return the duplicates as a List? Use .map(Map.Entry::getKey).toList() on the filtered entries.
  • Why boxed()? IntStream has no collect(Collector); grouping needs objects.
B11 Find even numbers from a list. Other rounds (Question List) 
List<Integer> evens = List.of(1, 2, 3, 4, 5, 6).stream().filter(n -> n % 2 == 0).toList();
// Output: [2, 4, 6]
import java.util.*;
import java.util.stream.*;

public class EvenNumbers {
    static List<Integer> evens(List<Integer> nums) {
        if (nums == null) return List.of();
        return nums.stream()
                .filter(Objects::nonNull)          // guard against null elements
                .filter(n -> n % 2 == 0)           // works for negatives: -4 % 2 == 0
                .toList();
    }

    static List<Integer> evensLoop(List<Integer> nums) {
        List<Integer> out = new ArrayList<>();
        for (Integer n : nums) if (n != null && (n & 1) == 0) out.add(n);
        return out;
    }

    public static void main(String[] args) {
        List<Integer> nums = Arrays.asList(1, 2, 3, 4, null, -6, 7, 8);
        System.out.println(evens(nums));                         // [2, 4, -6, 8]
        System.out.println(evensLoop(nums));                     // [2, 4, -6, 8]
        System.out.println(evens(List.of()));                    // []

        // Primitive variants: no boxing
        int[] arr = {10, 15, 20, 25};
        System.out.println(Arrays.toString(IntStream.of(arr).filter(x -> x % 2 == 0).toArray())); // [10, 20]
        System.out.println(IntStream.rangeClosed(1, 10).filter(x -> x % 2 == 0).sum()); // 30
    }
}

Complexity: O(n) time, O(n) output space. Gotcha: testing oddness with n % 2 == 1 fails for negative odd numbers, because -3 % 2 == -1. Use n % 2 != 0 or (n & 1) == 1. Edge cases: null list, null elements, empty list.

Likely follow-ups:

  • Remove the odd numbers in place? list.removeIf(n -> n % 2 != 0) on a mutable list.
  • Get evens and odds together? Collectors.partitioningBy(n -> n % 2 == 0) (see B28).
  • Is toList() mutable? No. Use collect(Collectors.toCollection(ArrayList::new)) if you need to modify the result.

(a) Count one character:

import java.util.*;
import java.util.function.Function;
import java.util.stream.*;

public class CharOccurrence {
    static long countChar(String s, char target) {
        if (s == null || s.isEmpty()) return 0;
        return s.chars().filter(c -> c == target).count();
    }

    static int countCharLoop(String s, char target) {
        int count = 0;
        for (int i = 0; i < s.length(); i++) if (s.charAt(i) == target) count++;
        return count;
    }

    // Trick: length difference after removal
    static int countCharReplace(String s, char target) {
        return s.length() - s.replace(String.valueOf(target), "").length();
    }

    // (b) Frequency map of all characters (ignoring spaces), in first-occurrence order
    static Map<Character, Long> frequency(String s) {
        if (s == null) return Map.of();
        return s.chars()
                .filter(c -> !Character.isWhitespace(c))
                .mapToObj(c -> (char) c)
                .collect(Collectors.groupingBy(Function.identity(), LinkedHashMap::new, Collectors.counting()));
    }

    // Array-based frequency for lowercase a-z
    static int[] frequencyArray(String s) {
        int[] f = new int[26];
        for (char c : s.toCharArray()) if (c >= 'a' && c <= 'z') f[c - 'a']++;
        return f;
    }

    public static void main(String[] args) {
        String s = "hello world";
        System.out.println(countChar(s, 'l'));        // 3
        System.out.println(countCharLoop(s, 'o'));    // 2
        System.out.println(countCharReplace(s, 'l')); // 3
        System.out.println(frequency(s));             // {h=1, e=1, l=3, o=2, w=1, r=1, d=1}
        System.out.println(frequencyArray(s)['l' - 'a']); // 3
        System.out.println(countChar("", 'x'));       // 0

        // Case-insensitive
        System.out.println("Banana".toLowerCase().chars().filter(c -> c == 'b').count()); // 1
    }
}

Complexity: O(n) time. Space: O(1) for counting one character, O(k) for the map, O(26) for the array. Gotchas: chars() returns an IntStream of UTF-16 code units, so (char) c is required for a Character key. For emoji or supplementary characters use codePoints(). Case sensitivity: normalise with toLowerCase(Locale.ROOT).

Likely follow-ups:

  • Most frequent character? frequency(s).entrySet().stream().max(Map.Entry.comparingByValue()).map(Map.Entry::getKey).
  • Why LinkedHashMap? Deterministic order for output and tests.
  • Count occurrences of a substring? Loop with indexOf(sub, from), or s.split(Pattern.quote(sub), -1).length - 1.

import java.util.*;
import java.util.stream.*;

public class FirstCharCount {
    static Map<Character, Long> countByFirstChar(List<String> words) {
        if (words == null) return Map.of();
        return words.stream()
                .filter(w -> w != null && !w.isEmpty())                 // charAt(0) would throw on ""
                .collect(Collectors.groupingBy(
                        w -> w.charAt(0),                                // classifier
                        LinkedHashMap::new,                              // keep encounter order
                        Collectors.counting()));                         // downstream
    }

    static Map<Character, Integer> countLoop(List<String> words) {
        Map<Character, Integer> m = new LinkedHashMap<>();
        for (String w : words) if (w != null && !w.isEmpty()) m.merge(w.charAt(0), 1, Integer::sum);
        return m;
    }

    public static void main(String[] args) {
        List<String> fruits = List.of("guava", "grapes", "apple", "orange");
        Map<Character, Long> result = countByFirstChar(fruits);
        System.out.println(result);                                      // {g=2, a=1, o=1}
        result.forEach((k, v) -> System.out.println(k + "-" + v));       // g-2 / a-1 / o-1
        System.out.println(countLoop(fruits));                           // {g=2, a=1, o=1}

        // Case-insensitive variant
        System.out.println(countByFirstChar(List.of("Guava", "grapes")).size()); // 2 (G and g differ)
        Map<Character, Long> ci = Stream.of("Guava", "grapes")
                .collect(Collectors.groupingBy(w -> Character.toLowerCase(w.charAt(0)),
                        LinkedHashMap::new, Collectors.counting()));
        System.out.println(ci);                                          // {g=2}
    }
}

Why LinkedHashMap? The 1-argument and 2-argument groupingBy use a HashMap. For Character keys a HashMap happens to iterate by hash (char code), giving {a=1, g=2, o=1}, which is not the order asked for. The 3-argument overload with a map factory gives you LinkedHashMap (insertion order) or TreeMap (sorted).

Complexity: O(n) time, O(k) space. Edge cases: empty strings (guarded), null list or elements, mixed case.

Likely follow-ups:

  • Get the words themselves grouped by first character? groupingBy(w -> w.charAt(0), LinkedHashMap::new, Collectors.toList()).
  • Return an Integer count instead of Long? Collectors.summingInt(w -> 1) or collectingAndThen(counting(), Long::intValue).
  • Sorted by count descending? Stream the entries and sort with Map.Entry.comparingByValue(Comparator.reverseOrder()) (see B26).
B14 Remove duplicates while maintaining order. G2 
List<Integer> r = List.of(3, 1, 3, 2, 1).stream().distinct().toList();

// Output: [3, 1, 2]
import java.util.*;
import java.util.stream.*;

public class RemoveDuplicates {
    // 1. distinct(): uses equals/hashCode and keeps the FIRST occurrence in encounter order
    static <T> List<T> dedupStream(List<T> list) {
        return list == null ? List.of() : list.stream().distinct().toList();
    }

    // 2. LinkedHashSet: classic, no streams
    static <T> List<T> dedupSet(List<T> list) {
        return new ArrayList<>(new LinkedHashSet<>(list));
    }

    // 3. Manual loop with a seen-set (lets you add custom logic)
    static <T> List<T> dedupLoop(List<T> list) {
        Set<T> seen = new HashSet<>();
        List<T> out = new ArrayList<>();
        for (T t : list) if (seen.add(t)) out.add(t);
        return out;
    }

    // 4. Deduplicate by a key (e.g. case-insensitive), keeping the first occurrence
    static List<String> dedupIgnoreCase(List<String> list) {
        Set<String> seen = new HashSet<>();
        return list.stream().filter(s -> seen.add(s.toLowerCase())).toList(); // stateful lambda: sequential only!
    }

    public static void main(String[] args) {
        List<Integer> nums = List.of(5, 3, 5, 1, 3, 7, 1);
        System.out.println(dedupStream(nums)); // [5, 3, 1, 7]
        System.out.println(dedupSet(nums));    // [5, 3, 1, 7]
        System.out.println(dedupLoop(nums));   // [5, 3, 1, 7]
        System.out.println(dedupIgnoreCase(List.of("Java", "java", "Go", "GO", "rust"))); // [Java, Go, rust]

        // Characters in a string
        String s = "programming";
        System.out.println(s.chars().distinct()
                .mapToObj(c -> String.valueOf((char) c)).collect(Collectors.joining())); // progamin
    }
}

reduce folds a stream into a single value by repeatedly applying a combining function. There are three overloads:

Overload Returns Use
reduce(BinaryOperator<T> acc) Optional<T> No identity, so an empty stream gives an empty Optional
reduce(T identity, BinaryOperator<T> acc) T Identity is returned for an empty stream
reduce(U identity, BiFunction<U,? super T,U> acc, BinaryOperator<U> combiner) U Result type differs from the element type; the combiner merges partial results in parallel 
import java.util.*;
import java.util.stream.*;

public class ReduceSum {
    public static void main(String[] args) {
        List<Integer> nums = List.of(1, 2, 3, 4, 5);

        int sum1 = nums.stream().reduce(0, Integer::sum);                    // 15
        int sum2 = nums.stream().reduce(0, (a, b) -> a + b);                 // 15
        Optional<Integer> sum3 = nums.stream().reduce(Integer::sum);         // Optional[15]
        Optional<Integer> empty = Stream.<Integer>empty().reduce(Integer::sum); // Optional.empty
        int sum4 = nums.stream().mapToInt(Integer::intValue).sum();          // 15, no boxing (preferred)
        int sum5 = nums.stream().collect(Collectors.summingInt(Integer::intValue)); // 15

        // 3-arg form: the result type (int) differs from the element type (String)
        List<String> words = List.of("java", "is", "fun");
        int totalLen = words.parallelStream().reduce(0,
                (partial, w) -> partial + w.length(),   // accumulator: (Integer, String) -> Integer
                Integer::sum);                          // combiner: merges partial sums
        System.out.println(totalLen);                                         // 9

        int product = nums.stream().reduce(1, (a, b) -> a * b);              // 120 (identity 1)
        int max = nums.stream().reduce(Integer.MIN_VALUE, Integer::max);     // 5

        // Overflow-safe sum of large values
        long big = Stream.of(Integer.MAX_VALUE, 1).mapToLong(Integer::longValue).sum(); // 2147483648

        // WRONG identity: 10 is not the identity of +
        int wrong = nums.parallelStream().reduce(10, Integer::sum);
        System.out.println(sum1 + " " + sum2 + " " + sum3 + " " + empty + " " + sum4 + " " + sum5
                + " " + product + " " + max + " " + big + " " + wrong);
        // 15 15 Optional[15] Optional.empty 15 15 120 5 2147483648 65 (wrong: 15 + 10*chunks, varies by core count)
    }
}

Rules: the identity must satisfy acc(identity, x) == x; the accumulator must be associative; and in the 3-argument form, combiner(u, acc(identity, t)) == acc(u, t).

reduce vs sum(): IntStream.sum() avoids boxing every element into an Integer and is easier to read. Use reduce for custom folds (product, max of a derived value, merging objects). For mutable accumulation (building a list or StringBuilder), use collect, not reduce. reduce should produce new immutable values each time.

Complexity: O(n) time, O(1) space.

Likely follow-ups:

  • Why does the 3-argument reduce need a combiner? In parallel each chunk produces a partial U, and partial Us cannot be fed back into an accumulator that expects a T.
  • reduce vs collect? reduce is immutable reduction (it combines values); collect is mutable reduction (it adds into a container).
  • Average with reduce? Better to use mapToInt(..).average() or Collectors.averagingInt / summaryStatistics().

import java.util.*;
import java.util.stream.*;

public class SecondHighest {
    static Optional<Integer> secondHighest(List<Integer> nums) {
        if (nums == null) return Optional.empty();
        return nums.stream()
                .filter(Objects::nonNull)
                .distinct()                              // important: [9, 9, 5] -> 5, not 9
                .sorted(Comparator.reverseOrder())
                .skip(1)
                .findFirst();
    }

    // Without a full sort: O(n)
    static Optional<Integer> secondHighestLinear(List<Integer> nums) {
        Integer first = null, second = null;
        for (Integer n : nums) {
            if (n == null || n.equals(first) || n.equals(second)) continue;
            if (first == null || n > first) { second = first; first = n; }
            else if (second == null || n > second) { second = n; }
        }
        return Optional.ofNullable(second);
    }

    public static void main(String[] args) {
        System.out.println(secondHighest(List.of(10, 40, 30, 40, 20)));       // Optional[30]
        System.out.println(secondHighest(List.of(7, 7, 7)));                  // Optional.empty
        System.out.println(secondHighest(List.of()));                         // Optional.empty
        System.out.println(secondHighestLinear(List.of(10, 40, 30, 40, 20))); // Optional[30]

        // Variant: second highest NOT distinct (the second element of the sorted list)
        System.out.println(Stream.of(40, 10, 40).sorted(Comparator.reverseOrder()).skip(1).findFirst()); // Optional[40]

        // Variant with a TreeSet
        TreeSet<Integer> ts = new TreeSet<>(List.of(10, 40, 30, 40, 20));
        System.out.println(ts.lower(ts.last()));                              // 30

        // Nth highest generalised
        int n = 3;
        System.out.println(Stream.of(10, 40, 30, 40, 20).distinct()
                .sorted(Comparator.reverseOrder()).skip(n - 1).findFirst().orElse(null)); // 20
    }
}

Always clarify with the interviewer whether "second highest" means distinct.

        if (x > first) { second = first; first = x; }
        else if (x < first && x > second) second = x;
    }
    return second == Long.MIN_VALUE ? OptionalInt.empty() : OptionalInt.of((int) second);
}
// secondLargest(new int[]{5, 9, 3, 9, 7}) -> OptionalInt[7]; {4, 4} or {} -> OptionalInt.empty

Using long sentinels means no real int value (including Integer.MIN_VALUE) can be mistaken for "not found".

Requirements: single pass O(n), handle duplicates ([5, 5, 3] gives 3), handle "no answer" (empty array, one element, all equal), and handle Integer.MIN_VALUE as a legitimate value.

import java.util.*;
import java.util.stream.*;

public class SecondLargestDistinct {

    /** Single pass, O(n) time, O(1) space. Returns OptionalInt.empty() when no answer exists. */
    public static OptionalInt secondLargest(int[] arr) {
        if (arr == null || arr.length < 2) return OptionalInt.empty();
        // long sentinels so Integer.MIN_VALUE can still be a real answer
        long first = Long.MIN_VALUE, second = Long.MIN_VALUE;
        for (int x : arr) {
            if (x > first) {            // new maximum: the old max becomes second
                second = first;
                first = x;
            } else if (x < first && x > second) {   // strictly less than max, so duplicates of max are skipped
                second = x;
            }
        }
        return second == Long.MIN_VALUE ? OptionalInt.empty() : OptionalInt.of((int) second);
    }

    /** Stream version: O(n log n) because of sorting. */
    public static OptionalInt secondLargestStream(int[] arr) {
        if (arr == null) return OptionalInt.empty();
        return Arrays.stream(arr)
                .boxed()
                .distinct()
                .sorted(Comparator.reverseOrder())
                .skip(1)
                .mapToInt(Integer::intValue)
                .findFirst();
    }

    /** Alternative contract: throw when there is no answer. */
    public static int secondLargestOrThrow(int[] arr) {
        return secondLargest(arr).orElseThrow(
                () -> new IllegalArgumentException("Array must contain at least two distinct values"));
    }

    public static void main(String[] args) {
        int[][] tests = {
                {12, 35, 1, 10, 34, 1},     // 34
                {10, 10, 10},               // none
                {5},                        // none
                {},                         // none
                {-1, -5, -3},               // -3
                {Integer.MIN_VALUE, 0},     // MIN_VALUE
                {7, 7, 3, 3},               // 3
                {1, 2}                      // 1
        };
        for (int[] t : tests) {
            System.out.printf("%-30s loop=%s stream=%s%n",
                    Arrays.toString(t), secondLargest(t), secondLargestStream(t));
        }
        System.out.println(secondLargest(null));
        try { secondLargestOrThrow(new int[]{4, 4}); }
        catch (IllegalArgumentException e) { System.out.println(e.getMessage()); }
    }
}

A HashMap has no order and a TreeMap sorts only by key, so to "sort by value" you stream the entries, sort them, and collect into a LinkedHashMap, which keeps insertion order.

import java.util.*;
import java.util.stream.*;

public class SortMapByValue {
    public static void main(String[] args) {
        Map<String, Integer> scores = new HashMap<>(Map.of("Asha", 82, "Ravi", 95, "John", 70, "Meera", 95));

        // Ascending by value
        LinkedHashMap<String, Integer> asc = scores.entrySet().stream()
                .sorted(Map.Entry.comparingByValue())
                .collect(Collectors.toMap(Map.Entry::getKey, Map.Entry::getValue,
                        (a, b) -> a, LinkedHashMap::new));
        System.out.println(asc);    // {John=70, Asha=82, Meera=95, Ravi=95} (tie order depends on HashMap iteration)

        // Descending by value, ties broken by key ascending (deterministic)
        LinkedHashMap<String, Integer> desc = scores.entrySet().stream()
                .sorted(Map.Entry.<String, Integer>comparingByValue(Comparator.reverseOrder())
                        .thenComparing(Map.Entry.comparingByKey()))
                .collect(Collectors.toMap(Map.Entry::getKey, Map.Entry::getValue,
                        (a, b) -> a, LinkedHashMap::new));
        System.out.println(desc);   // {Meera=95, Ravi=95, Asha=82, John=70}

        // Top 2
        System.out.println(desc.entrySet().stream().limit(2).map(Map.Entry::getKey).toList()); // [Meera, Ravi]

        // Pre-Java 8 approach
        List<Map.Entry<String, Integer>> entries = new ArrayList<>(scores.entrySet());
        entries.sort(Map.Entry.comparingByValue());
        Map<String, Integer> manual = new LinkedHashMap<>();
        for (Map.Entry<String, Integer> e : entries) manual.put(e.getKey(), e.getValue());
        System.out.println(manual.values()); // [70, 82, 95, 95]
    }
}

Why the merge function (a, b) -> a? The 4-argument toMap is the only overload that takes a map supplier, so you must supply a merge function even though keys from a map are already unique.

Complexity: O(n log n) time, O(n) space. Gotchas:

  • Collecting into a plain toMap (a HashMap) throws the sorting away. This is the most common bug.
  • Map.Entry.<String,Integer>comparingByValue(...) needs explicit type witnesses when it is chained, otherwise inference fails.
  • A TreeMap with a value-based comparator is a trap: it breaks get() and silently drops entries with equal values.
  • Null values throw NPE in comparingByValue.

Likely follow-ups:

  • Sort by key? new TreeMap<>(map) or comparingByKey().
  • Word-frequency top N? groupingBy(w -> w, counting()), then sort the entries by value descending, then limit(N).
  • Can you keep a map always sorted by value? Not with standard maps. Use a TreeMap plus a reverse index, or sort on read.

public class MultiFilter {

                new Employee("Asha", "IT", 90_000, 30, true),
                new Employee("Ravi", "HR", 50_000, 45, true),

                .filter(e -> "IT".equals(e.dept()))
                .filter(e -> e.salary() > 50_000)
                .filter(Employee::active)
                .map(Employee::name).toList());                         // [Asha, Meera]

        Predicate<Employee> senior = e -> e.age() >= 40;
        Predicate<Employee> active = Employee::active;

        Predicate<Employee> rule = inIT.and(wellPaid).and(active).or(senior);
        System.out.println(emps.stream().filter(rule).map(Employee::name).toList()); // [Asha, Ravi, Meera]
        System.out.println(emps.stream().filter(active.negate()).map(Employee::name).toList()); // [John]
        System.out.println(emps.stream().filter(Predicate.not(Employee::active)).count());     // 1

        List<Predicate<Employee>> criteria = List.of(inIT, active);
        Predicate<Employee> all = criteria.stream().reduce(x -> true, Predicate::and);

B30 Caching with ConcurrentHashMap.computeIfAbsent().

computeIfAbsent is atomic per key: the loader runs at most once for each missing key, even when many threads call it at once. Keep the loader short, and never update the same map recursively from inside it (that throws IllegalStateException).

private final Map<Long, User> cache = new ConcurrentHashMap<>();
User getUser(long id) {
    return cache.computeIfAbsent(id, k -> userRepository.findById(k)); // DB hit only on first call
}

computeIfAbsent(key, mappingFunction) atomically does "if absent, compute and insert, then return the value". In ConcurrentHashMap (CHM) the function runs at most once per key, even under contention, because the bin is locked during computation. That makes it a one-line, thread-safe memoising cache.

import java.util.*;
import java.util.concurrent.*;
import java.util.function.Function;

public class ComputeIfAbsentCache {

    // Simple thread-safe memoiser
    static <K, V> Function<K, V> memoize(Function<K, V> fn) {
        Map<K, V> cache = new ConcurrentHashMap<>();
        return key -> cache.computeIfAbsent(key, fn);
    }

    static String slowLookup(String id) {
        System.out.println("  loading " + id + " on " + Thread.currentThread().getName());
        try { Thread.sleep(200); } catch (InterruptedException e) { Thread.currentThread().interrupt(); }
        return "User-" + id;
    }

    // ---- The recursive-update pitfall ----
    static final Map<Integer, Long> FIB = new ConcurrentHashMap<>();

    static long fibBroken(int n) {
        if (n <= 1) return n;
        // Modifies the SAME map from inside the mapping function
        return FIB.computeIfAbsent(n, k -> fibBroken(k - 1) + fibBroken(k - 2));
    }

    // Fix: compute outside, then insert
    static final Map<Integer, Long> FIB_OK = new ConcurrentHashMap<>();
    static long fibSafe(int n) {
        if (n <= 1) return n;
        Long cached = FIB_OK.get(n);
        if (cached != null) return cached;
        long v = fibSafe(n - 1) + fibSafe(n - 2);
        FIB_OK.putIfAbsent(n, v);
        return v;
    }

    public static void main(String[] args) throws Exception {
        Function<String, String> cachedLookup = memoize(ComputeIfAbsentCache::slowLookup);
        ExecutorService pool = Executors.newFixedThreadPool(4);
        List<Future<String>> fs = new ArrayList<>();
        for (int i = 0; i < 4; i++) fs.add(pool.submit(() -> cachedLookup.apply("42")));
        for (Future<String> f : fs) System.out.println(f.get());   // "loading 42" printed ONCE, then User-42 x4
        pool.shutdown();

        try {
            System.out.println(fibBroken(20));
        } catch (IllegalStateException e) {
            System.out.println("Pitfall: " + e.getMessage());     // Recursive update
        }
        System.out.println(fibSafe(50));                          // 12586269025
    }
}

The recursive-update pitfall:

  • The CHM Javadoc says: "The mapping function must not attempt to update any other mappings of this map."
  • Inside computeIfAbsent, CHM puts a ReservationNode in the bin and holds its lock. If the function calls computeIfAbsent on the same map for a key that hashes to the same bin (or triggers a resize), it detects the re-entry.
  • Java 9+: throws IllegalStateException: Recursive update. With small maps nearly every recursive call collides with something, so it fails reliably.
  • Java 8: could livelock / spin forever (JDK-8062841), which is a nasty production hang.
  • HashMap.computeIfAbsent with recursion throws ConcurrentModificationException (Java 9+) or silently corrupts the map.
  • Fixes: compute outside the map and then putIfAbsent (as shown); or use a different structure (an array for DP); or use Caffeine's LoadingCache (still no recursion).

Other gotchas:

  • Keep the mapping function short and non-blocking. It holds a bin lock, so a slow remote call blocks other writers to that bin (and readers of that key wait for it).
  • A function returning null means "do not insert", and the next caller recomputes.
  • If the function throws, nothing is inserted and the exception propagates.
  • Java 8's CHM computeIfAbsent locked even when the key was present (JDK-8161372). The common workaround is V v = map.get(k); return v != null ? v : map.computeIfAbsent(k, f);. This was fixed in Java 9.
  • CHM is an unbounded cache, with no eviction or TTL. In production use Caffeine (Caffeine.newBuilder().maximumSize(10_000).expireAfterWrite(10, MINUTES).build(loader)) or Spring's @Cacheable.
  • computeIfAbsent(k, x -> new ArrayList<>()).add(v) is the idiomatic multimap, but the ArrayList itself is not thread-safe. Use CopyOnWriteArrayList or ConcurrentHashMap.newKeySet().

Likely follow-ups:

  • putIfAbsent vs computeIfAbsent? putIfAbsent needs the value already computed (eager); computeIfAbsent computes lazily and only once.
  • Is get blocked during computation? get on a different key is not blocked; get on the same key returns null until the computation finishes (it does not wait). Only computeIfAbsent callers for that key wait.
  • Why not synchronized around a HashMap? A global lock serialises everything; CHM locks per bin.

import java.util.*;
import java.util.function.*;
import java.util.stream.*;

public class UpperJoinCollector {

    // Approach 1: implement the Collector interface
    static class UpperCaseJoining implements Collector<String, StringJoiner, String> {
        private final String delimiter;
        UpperCaseJoining(String delimiter) { this.delimiter = delimiter; }

        @Override public Supplier<StringJoiner> supplier() { return () -> new StringJoiner(delimiter); }
        @Override public BiConsumer<StringJoiner, String> accumulator() {
            return (sj, s) -> { if (s != null) sj.add(s.toUpperCase(Locale.ROOT)); };
        }
        @Override public BinaryOperator<StringJoiner> combiner() { return StringJoiner::merge; }
        @Override public Function<StringJoiner, String> finisher() { return StringJoiner::toString; }
        @Override public Set<Characteristics> characteristics() { return Collections.emptySet(); }
    }

    // Approach 2: Collector.of factory
    static Collector<String, StringJoiner, String> upperJoining(String delim, String prefix, String suffix) {
        return Collector.of(
                () -> new StringJoiner(delim, prefix, suffix),
                (sj, s) -> sj.add(s.toUpperCase(Locale.ROOT)),
                StringJoiner::merge,
                StringJoiner::toString);
    }

    // Approach 3: compose existing collectors (simplest in real code)
    static Collector<String, ?, String> upperJoiningSimple(String delim) {
        return Collectors.mapping(s -> s.toUpperCase(Locale.ROOT), Collectors.joining(delim));
    }

    public static void main(String[] args) {
        List<String> words = List.of("java", "spring", "kafka", "docker");
        System.out.println(words.stream().collect(new UpperCaseJoining(", ")));   // JAVA, SPRING, KAFKA, DOCKER
        System.out.println(words.stream().collect(upperJoining("|", "[", "]")));  // [JAVA|SPRING|KAFKA|DOCKER]
        System.out.println(words.stream().collect(upperJoiningSimple("-")));      // JAVA-SPRING-KAFKA-DOCKER

        // Parallel works because the combiner preserves order
        System.out.println(words.parallelStream().collect(new UpperCaseJoining(","))); // JAVA,SPRING,KAFKA,DOCKER

        // Usable as a downstream collector too
        record Emp(String name, String dept) {}
        Map<String, String> byDept = Stream.of(new Emp("ana", "IT"), new Emp("raj", "IT"), new Emp("li", "HR"))
                .collect(Collectors.groupingBy(Emp::dept, TreeMap::new,
                        Collectors.mapping(Emp::name, upperJoining(",", "", ""))));
        System.out.println(byDept);                                                  // {HR=LI, IT=ANA,RAJ}

        System.out.println("[" + Stream.<String>empty().collect(new UpperCaseJoining(",")) + "]"); // []
    }
}

How collect uses it (sequential): A a = supplier.get(); for each t: accumulator.accept(a, t); return finisher.apply(a);. In parallel, each chunk gets its own container from the supplier, and combiner merges them in encounter order (unless the collector is UNORDERED).

Characteristics:

  • IDENTITY_FINISH: the container is the result, so the finisher is skipped (for example toList). It does not apply here, since StringJoiner and String differ.
  • UNORDERED: order of results does not matter (toSet).
  • CONCURRENT: one shared container may be accumulated from many threads (requires a thread-safe container).

Complexity: O(total characters).

Likely follow-ups:

  • Why is StringJoiner::merge a valid combiner? merge(other) appends the other's content (without its prefix and suffix) and returns this, which matches BinaryOperator.
  • When would you write a custom collector? When no combination of mapping/reducing/collectingAndThen/teeing expresses the logic, for example top-N, batching into chunks, or custom statistics.
  • What happens if you wrongly mark it IDENTITY_FINISH? The finisher is skipped and an unchecked cast happens, giving a ClassCastException at the call site.

import java.io.*;
import java.nio.charset.StandardCharsets;
import java.nio.file.*;
import java.util.*;
import java.util.stream.*;

public class LargeFileStreaming {

    // 1. Files.lines: lazy, needs try-with-resources (it holds an open file handle)
    static long countErrors(Path file) throws IOException {
        try (Stream<String> lines = Files.lines(file, StandardCharsets.UTF_8)) {
            return lines.filter(l -> l.contains("ERROR")).count();
        }
    }

    // 2. BufferedReader.lines: same laziness, useful for InputStreams (classpath, HTTP, gzip)
    static List<String> firstNErrors(InputStream in, int n) throws IOException {
        try (BufferedReader br = new BufferedReader(new InputStreamReader(in, StandardCharsets.UTF_8))) {
            return br.lines().filter(l -> l.contains("ERROR")).limit(n).toList(); // stops reading early
        }
    }

    // 3. Classic loop: full control, easy to handle per-line exceptions and to track line numbers
    static Map<String, Long> levelCounts(Path file) throws IOException {
        Map<String, Long> counts = new TreeMap<>();
        try (BufferedReader br = Files.newBufferedReader(file)) {
            String line;
            while ((line = br.readLine()) != null) {
                String level = line.split(" ", 2)[0];
                counts.merge(level, 1L, Long::sum);
            }
        }
        return counts;
    }

    public static void main(String[] args) throws IOException {
        Path tmp = Files.createTempFile("app", ".log");
        try (BufferedWriter w = Files.newBufferedWriter(tmp)) {
            for (int i = 0; i < 100_000; i++) w.write((i % 10 == 0 ? "ERROR" : "INFO") + " line " + i + "\n");
        }
        System.out.println(countErrors(tmp));                                     // 10000
        System.out.println(firstNErrors(Files.newInputStream(tmp), 2));          // [ERROR line 0, ERROR line 10]
        System.out.println(levelCounts(tmp));                                     // {ERROR=10000, INFO=90000}
        Files.delete(tmp);
    }
}

Memory characteristics:

  • Files.lines / BufferedReader.lines read lazily through a buffer (8 KB by default), so memory is O(longest line) as long as your terminal operation does not accumulate. count(), forEach, filtering into a small result, and limit are all fine.
  • Files.readAllLines / Files.readString load the entire file into memory, which can cause OutOfMemoryError on multi-GB files.
  • sorted(), distinct(), or collect(toList()) on all lines buffer everything. Avoid them on huge inputs, or use external sorting.

Gotchas:

  • Always close the Files.lines stream (try-with-resources). It wraps an open file descriptor, and leaking it causes "Too many open files". This is one of the few streams you must close.
  • Malformed input for the charset throws UncheckedIOException (wrapping MalformedInputException) during iteration, not at open time.
  • Files.lines parallelises reasonably on JDK 9+ for UTF-8, US-ASCII, and ISO-8859-1 files (it memory-maps and splits on line breaks). BufferedReader.lines does not parallelise well.
  • For gzip input: new BufferedReader(new InputStreamReader(new GZIPInputStream(Files.newInputStream(p)))).
  • For huge files with processing that is heavy per line, consider batching plus an executor, Spring Batch, or memory-mapped FileChannel.

Likely follow-ups:

  • How do you get line numbers? Use a BufferedReader loop with a counter, or LineNumberReader. Streams have no index.
  • Process a 10 GB file faster? Split by byte ranges and run parallel workers, or use Files.lines(...).parallel() on JDK 9+. Benchmark, because disk I/O is usually the bottleneck.
  • Why does Files.lines throw UncheckedIOException? Lambdas and stream methods cannot throw checked IOException.

import java.util.*;
import java.util.function.*;
import java.util.stream.*;

public class GenericFunctional {

    // Filter + transform any list. PECS wildcards make it maximally reusable.
    public static <T, R> List<R> filterAndMap(Collection<? extends T> source,
                                              Predicate<? super T> filter,
                                              Function<? super T, ? extends R> mapper) {
        if (source == null || source.isEmpty()) return List.of();
        List<R> out = new ArrayList<>();
        for (T t : source) if (filter.test(t)) out.add(mapper.apply(t));
        return out;
    }

    // Generic fold
    public static <T, A> A fold(Iterable<T> items, A initial, BiFunction<A, ? super T, A> step) {
        A acc = initial;
        for (T t : items) acc = step.apply(acc, t);
        return acc;
    }

    // Retry helper: shows Supplier + exception handling
    public static <T> T retry(Supplier<T> action, int attempts, Predicate<Exception> retryOn) {
        RuntimeException last = null;
        for (int i = 1; i <= attempts; i++) {
            try { return action.get(); }
            catch (RuntimeException e) {
                last = e;
                if (!retryOn.test(e)) throw e;
                System.out.println("attempt " + i + " failed: " + e.getMessage());
            }
        }
        throw last;
    }

    // Grouping helper with a bounded type parameter
    public static <T, K extends Comparable<K>> SortedMap<K, List<T>> groupSorted(List<T> items, Function<T, K> key) {
        return items.stream().collect(Collectors.groupingBy(key, TreeMap::new, Collectors.toList()));
    }

    // Custom functional interface that allows checked exceptions
    @FunctionalInterface
    interface ThrowingFunction<T, R> { R apply(T t) throws Exception; }

    static <T, R> Function<T, R> unchecked(ThrowingFunction<T, R> f) {
        return t -> {
            try { return f.apply(t); }
            catch (Exception e) { throw new RuntimeException(e); }
        };
    }

    public static void main(String[] args) {
        List<Integer> nums = List.of(1, 2, 3, 4, 5, 6);
        List<String> labels = filterAndMap(nums, n -> n % 2 == 0, n -> "#" + n);
        System.out.println(labels);                                              // [#2, #4, #6]

        // Wildcards in action: Predicate<Object> works for Integers
        Predicate<Object> notNull = Objects::nonNull;
        List<Number> asNumbers = filterAndMap(nums, notNull, n -> n * 1.5);
        System.out.println(asNumbers);                                           // [1.5, 3.0, 4.5, 6.0, 7.5, 9.0]

        System.out.println(fold(nums, 0, Integer::sum));                         // 21
        System.out.println(fold(List.of("a", "b"), new StringBuilder(), StringBuilder::append)); // ab

        int[] calls = {0};
        String r = retry(() -> { if (++calls[0] < 3) throw new IllegalStateException("flaky"); return "ok"; },
                5, e -> e instanceof IllegalStateException);
        System.out.println(r);                                                    // ok (after 2 failures)

        System.out.println(groupSorted(List.of("kiwi", "fig", "plum", "pear"), String::length)); // {3=[fig], 4=[kiwi, plum, pear]}

        System.out.println(Stream.of("1", "2").map(unchecked(Integer::parseInt)).toList()); // [1, 2]
    }
}

Design notes:

  • PECS ("Producer Extends, Consumer Super"): a Predicate<? super T> consumes T, so a Predicate<Object> can be reused for any type. A Function<? super T, ? extends R> consumes T and produces R.
  • Type parameters are declared before the return type: public static <T, R> ....
  • Callers rarely need explicit witnesses (GenericFunctional.<Integer,String>filterAndMap(...)) because inference handles them.
  • This is the Strategy pattern without classes. Spring's JdbcTemplate.query(sql, RowMapper<T>) and TransactionTemplate.execute(TransactionCallback<T>) work the same way.

Complexity: O(n) for filterAndMap/fold.

Likely follow-ups:

  • Why ? super T on the Predicate? It accepts predicates written for supertypes (for example Predicate<Object>), which makes the API more flexible.
  • How do you handle checked exceptions in a lambda? A custom functional interface plus a wrapper (as shown), or libraries such as Vavr's CheckedFunction.
  • Can a generic method be overloaded only by different functional interfaces? It can, but lambdas then become ambiguous at call sites. Avoid it.

import java.io.*;
import java.nio.file.*;
import java.util.*;
import java.util.stream.*;

public class CsvPipeline {
    record Employee(int id, String name, String dept, double salary, boolean active) {}

    record ParseResult(Employee employee, String error) {
        static ParseResult ok(Employee e) { return new ParseResult(e, null); }
        static ParseResult fail(String err) { return new ParseResult(null, err); }
        boolean isOk() { return employee != null; }
    }

    static Optional<Employee> parse(String line) {
        try {
            String[] p = line.split(",", -1);              // -1 keeps trailing empty fields
            if (p.length != 5) throw new IllegalArgumentException("expected 5 columns, got " + p.length);
            return Optional.of(new Employee(
                    Integer.parseInt(p[0].trim()),
                    p[1].trim(),
                    p[2].trim(),
                    Double.parseDouble(p[3].trim()),
                    Boolean.parseBoolean(p[4].trim())));
        } catch (RuntimeException e) {                     // NumberFormatException, IllegalArgumentException
            System.err.println("Skipping bad row [" + line + "]: " + e.getMessage());
            return Optional.empty();
        }
    }

    static ParseResult parseWithResult(String line) {
        return parse(line).map(ParseResult::ok).orElseGet(() -> ParseResult.fail(line));
    }

    public static void main(String[] args) throws IOException {
        Path csv = Files.createTempFile("emps", ".csv");
        Files.writeString(csv, String.join("\n",
                "id,name,dept,salary,active",
                "1,Asha,IT,90000,true",
                "2,Ravi,HR,50000,true",
                "3,John,IT,abc,true",           // bad salary
                "4,Meera,IT,120000,false",
                "",                             // blank line
                "5,Kiran,IT,65000,true",
                "6,Li,Finance,80000"));         // missing column

        try (Stream<String> lines = Files.lines(csv)) {
            List<String> names = lines
                    .skip(1)                                    // header
                    .filter(l -> !l.isBlank())
                    .map(CsvPipeline::parse)
                    .flatMap(Optional::stream)                  // drop unparseable rows
                    .filter(Employee::active)
                    .filter(e -> "IT".equals(e.dept()))
                    .filter(e -> e.salary() > 60_000)
                    .sorted(Comparator.comparingDouble(Employee::salary).reversed())
                    .map(Employee::name)
                    .toList();
            System.out.println(names);                          // [Asha, Kiran]
        }

        // Second pass: aggregate per department, and count errors explicitly
        try (Stream<String> lines = Files.lines(csv)) {
            Map<Boolean, List<ParseResult>> results = lines.skip(1).filter(l -> !l.isBlank())
                    .map(CsvPipeline::parseWithResult)
                    .collect(Collectors.partitioningBy(ParseResult::isOk));
            Map<String, Double> totalByDept = results.get(true).stream()
                    .map(ParseResult::employee)
                    .collect(Collectors.groupingBy(Employee::dept, TreeMap::new,
                            Collectors.summingDouble(Employee::salary)));
            System.out.println(totalByDept);                    // {HR=50000.0, IT=275000.0}
            System.out.println("bad rows: " + results.get(false).size()); // bad rows: 2
        }
        Files.delete(csv);
    }
}

Design points to talk about:

  • Skip the header with skip(1). Alternatively, read the first line separately to map column names to indexes, which is resilient to column reordering.
  • Error handling inside lambdas: a lambda cannot throw checked exceptions, and one bad row should not kill the whole job. Return Optional/Either/a result object, log, and continue. For strict mode, throw a custom unchecked exception that includes the line number.
  • split(",", -1) keeps trailing empty columns. A naive split(",") drops them and cannot handle quoted commas. For real CSV use Apache Commons CSV, OpenCSV, or Jackson CSV.
  • Records (Java 16) make immutable DTOs a one-liner, with equals/hashCode/toString included.

import java.util.*;
import java.util.stream.*;

public class LongestString {
    static Optional<String> longest(List<String> words) {
        if (words == null) return Optional.empty();
        return words.stream()
                .filter(Objects::nonNull)
                .max(Comparator.comparingInt(String::length));
    }

    static List<String> allLongest(List<String> words) {
        int maxLen = words.stream().mapToInt(String::length).max().orElse(0);
        return words.stream().filter(w -> w.length() == maxLen).toList();
    }

    public static void main(String[] args) {
        List<String> words = List.of("java", "microservices", "spring", "observability", "go");

        System.out.println(longest(words).orElse("none"));              // microservices (13, first of the tie)
        System.out.println(allLongest(words));                          // [microservices, observability]
        System.out.println(longest(List.of()).orElse("none"));          // none

        // Shortest
        System.out.println(words.stream().min(Comparator.comparingInt(String::length)).get()); // go

        // Longest, with ties broken alphabetically (last alphabetically wins with max)
        System.out.println(words.stream()
                .max(Comparator.comparingInt(String::length).thenComparing(Comparator.naturalOrder())).get()); // observability

        // reduce equivalent
        System.out.println(words.stream().reduce((a, b) -> a.length() >= b.length() ? a : b).get()); // microservices

        // Longest word in a sentence
        String sentence = "Streams make Java collections expressive";
        System.out.println(Arrays.stream(sentence.split("\\s+"))
                .max(Comparator.comparingInt(String::length)).orElse(""));   // collections

        // Loop
        String best = null;
        for (String w : words) if (best == null || w.length() > best.length()) best = w;
        System.out.println(best);                                       // microservices
    }
}

Tie behaviour: Stream.max is implemented as reduce(BinaryOperator.maxBy(cmp)), and maxBy returns cmp.compare(a, b) >= 0 ? a : b. So for equal lengths it keeps the first encountered element (and min also keeps the first). Do not rely on this in parallel unless the stream is ordered, which it is for lists.

Complexity: O(n) time, O(1) space (allLongest takes two passes, still O(n)). Gotchas: max returns Optional, so calling .get() on an empty list throws. Use comparingInt rather than comparing(String::length) to avoid boxing. Null elements would NPE inside String::length.

import java.util.*;
import java.util.regex.Pattern;
import java.util.stream.*;

public class UpperWithStreams {
    // Word-wise: split, map, join (normalises runs of whitespace to a single space)
    static String upperWords(String s) {
        if (s == null || s.isBlank()) return s;
        return Arrays.stream(s.trim().split("\\s+"))
                .map(String::toUpperCase)
                .collect(Collectors.joining(" "));
    }

    // Word-wise, Pattern.splitAsStream (avoids the intermediate array)
    private static final Pattern WS = Pattern.compile("\\s+");
    static String upperWords2(String s) {
        return WS.splitAsStream(s).map(String::toUpperCase).collect(Collectors.joining(" "));
    }

    // Character-wise: preserves the exact spacing
    static String upperChars(String s) {
        if (s == null) return null;
        return s.chars()
                .map(Character::toUpperCase)
                .collect(StringBuilder::new, StringBuilder::appendCodePoint, StringBuilder::append)
                .toString();
    }

    // Character-wise via mapToObj + joining (simpler to read, more allocation)
    static String upperChars2(String s) {
        return s.chars().mapToObj(c -> String.valueOf((char) Character.toUpperCase(c)))
                .collect(Collectors.joining());
    }

    // Bonus: Title Case ("This Is Test")
    static String titleCase(String s) {
        return Arrays.stream(s.trim().split("\\s+"))
                .map(w -> Character.toUpperCase(w.charAt(0)) + w.substring(1).toLowerCase())
                .collect(Collectors.joining(" "));
    }

    public static void main(String[] args) {
        String in = "this is test";
        System.out.println(upperWords(in));          // THIS IS TEST
        System.out.println(upperWords2(in));         // THIS IS TEST
        System.out.println(upperChars(in));          // THIS IS TEST
        System.out.println(upperChars2(in));         // THIS IS TEST
        System.out.println(titleCase(in));           // This Is Test
        System.out.println(in.toUpperCase());        // THIS IS TEST (the obvious non-stream answer)

        System.out.println("[" + upperWords("  this   is  test ") + "]"); // [THIS IS TEST] (spacing normalised)
        System.out.println("[" + upperChars("  this   is  test ") + "]"); // [  THIS   IS  TEST ] (spacing kept)

        // Reverse each word as well (a common twist)
        System.out.println(Arrays.stream(in.split(" "))
                .map(w -> new StringBuilder(w).reverse().toString().toUpperCase())
                .collect(Collectors.joining(" ")));  // SIHT SI TSET

}

This phrase is ambiguous, so clarify it with the interviewer. The two usual meanings are:

(a) Lexicographically largest substring

Key insight: the lexicographically largest substring is always a suffix. If substring s[i..j] is the best, extending it to s[i..n-1] only makes it larger, because a string is smaller than any string it is a proper prefix of. So the answer is the maximum suffix.

  • Brute force: compare all n suffixes, O(n^2) worst case (for example "aaaa...a").

  • O(n) two-pointer (LeetCode 1163 "Last Substring in Lexicographical Order"): keep candidate start i, challenger j, and matched length k.

    • If s[i+k] == s[j+k], increment k.
    • If s[i+k] < s[j+k], the challenger wins. Every start from i to i+k is beaten as well, so i = max(i+k+1, j), j = i+1, k = 0.
    • If s[i+k] > s[j+k], the candidate wins. Every start from j to j+k is beaten, so j = j+k+1, k = 0.

    Each step advances i + j + k by at least 1, so it is linear.

import java.util.*;
import java.util.stream.*;

public class HighestSubstring {

    /** (a) Lexicographically largest substring = max suffix. O(n) time, O(1) space. */
    static String lastSubstring(String s) {
        if (s == null || s.isEmpty()) return "";
        int n = s.length(), i = 0, j = 1, k = 0;
        while (j + k < n) {
            char a = s.charAt(i + k), b = s.charAt(j + k);
            if (a == b) {
                k++;
            } else if (a < b) {            // challenger j is better
                i = Math.max(i + k + 1, j);
                j = i + 1;
                k = 0;
            } else {                       // candidate i is better
                j = j + k + 1;
                k = 0;
            }
        }
        return s.substring(i);
    }

    /** (a) Stream brute force, O(n^2): all suffixes, take the max. */
    static String lastSubstringStream(String s) {
        return IntStream.range(0, s.length()).mapToObj(s::substring)
                .max(Comparator.naturalOrder()).orElse("");
    }

    /** (b) Longest substring without repeating characters. Sliding window, O(n). */
    static String longestUniqueSubstring(String s) {
        if (s == null || s.isEmpty()) return "";
        int[] lastSeen = new int[128];            // ASCII; use Map<Character,Integer> for full Unicode
        Arrays.fill(lastSeen, -1);
        int left = 0, bestStart = 0, bestLen = 0;
        for (int right = 0; right < s.length(); right++) {
            char c = s.charAt(right);
            if (lastSeen[c] >= left) left = lastSeen[c] + 1;   // jump past the previous occurrence
            lastSeen[c] = right;
            if (right - left + 1 > bestLen) { bestLen = right - left + 1; bestStart = left; }
        }
        return s.substring(bestStart, bestStart + bestLen);
    }

    /** (b) Variant using a HashMap (Unicode-safe for BMP characters). */
    static int lengthOfLongestUnique(String s) {
        Map<Character, Integer> last = new HashMap<>();
        int left = 0, best = 0;
        for (int r = 0; r < s.length(); r++) {
            Integer prev = last.put(s.charAt(r), r);
            if (prev != null && prev >= left) left = prev + 1;
            best = Math.max(best, r - left + 1);
        }
        return best;
    }

    public static void main(String[] args) {
        System.out.println(lastSubstring("abab"));           // bab
        System.out.println(lastSubstring("leetcode"));       // tcode
        System.out.println(lastSubstring("zazzb"));          // zzb
        System.out.println(lastSubstringStream("leetcode")); // tcode

        System.out.println(longestUniqueSubstring("abcabcbb")); // abc
        System.out.println(longestUniqueSubstring("bbbbb"));    // b
        System.out.println(longestUniqueSubstring("pwwkew"));   // wke
        System.out.println(lengthOfLongestUnique("dvdf"));      // 3 (vdf)
        System.out.println("[" + longestUniqueSubstring("") + "]"); // []
    }
}

public class FirstNonRepeating {

    // Stream + LinkedHashMap (keeps first-occurrence order)
    static Optional<Character> firstUniqueStream(String s) {
        if (s == null || s.isEmpty()) return Optional.empty();
        return s.chars()
                .mapToObj(c -> (char) c)
                .collect(Collectors.groupingBy(Function.identity(), LinkedHashMap::new, Collectors.counting()))
                .entrySet().stream()
                .filter(e -> e.getValue() == 1L)
                .map(Map.Entry::getKey)
                .findFirst();
    }

    // O(n) two passes over a counting array: fastest, O(1) space (fixed 256 / 65536 slots)
    static int firstUniqueIndex(String s) {
        if (s == null) return -1;
        int[] count = new int[Character.MAX_VALUE + 1];   // or 26 for 'a'-'z', 256 for extended ASCII
        for (int i = 0; i < s.length(); i++) count[s.charAt(i)]++;
        for (int i = 0; i < s.length(); i++) if (count[s.charAt(i)] == 1) return i;
        return -1;
    }

    // Single pass over the string, then a pass over at most 26 letters (very long strings, small alphabet)
    static int firstUniqueIndexSinglePass(String s) {
        int[] firstIdx = new int[26];
        Arrays.fill(firstIdx, -1);                 // -1 = unseen, -2 = repeated
        for (int i = 0; i < s.length(); i++) {
            int c = s.charAt(i) - 'a';
            firstIdx[c] = firstIdx[c] == -1 ? i : -2;
        }
        int best = Integer.MAX_VALUE;
        for (int idx : firstIdx) if (idx >= 0) best = Math.min(best, idx);
        return best == Integer.MAX_VALUE ? -1 : best;
    }

    // The indexOf/lastIndexOf trick: O(n^2), but a short answer
    static Optional<Character> firstUniqueTrick(String s) {
        return s.chars().filter(c -> s.indexOf(c) == s.lastIndexOf(c))
                .mapToObj(c -> (char) c).findFirst();
    }

        System.out.println(firstUniqueIndex(""));                  // -1

B39 Remove duplicate letters, smallest lexicographic result (LeetCode 316).

Greedy with a monotonic stack. Pop a larger character off the top if it appears again later. Skip characters already on the stack. O(n).

static String removeDuplicateLetters(String s) {
    int[] last = new int[26];
    for (int i = 0; i < s.length(); i++) last[s.charAt(i) - 'a'] = i;
    boolean[] inStack = new boolean[26];
    StringBuilder st = new StringBuilder();          // used as a stack
    for (int i = 0; i < s.length(); i++) {
        char c = s.charAt(i);
        if (inStack[c - 'a']) continue;
        while (st.length() > 0 && st.charAt(st.length() - 1) > c
                && last[st.charAt(st.length() - 1) - 'a'] > i) {
            inStack[st.charAt(st.length() - 1) - 'a'] = false;
            st.deleteCharAt(st.length() - 1);
        }
        st.append(c);
        inStack[c - 'a'] = true;
    }
    return st.toString();
}
// "bcabc" -> abc ; "cbacdcbc" -> acdb

Problem: remove duplicate letters so that every letter appears exactly once, and the result is the lexicographically smallest among all possible results. It must be a subsequence, so the relative order is kept. "bcabc" gives "abc"; "cbacdcbc" gives "acdb".

Why a monotonic stack (greedy)? We build the answer left to right and want small characters as early as possible. When we see character c, and the stack top is greater than c and that top character appears again later, we can safely pop it: putting c earlier makes the string smaller, and we can re-add the popped character later. If the top does not appear later, we must keep it (it is the last chance to include it). Characters already in the stack are skipped, because the earlier position is already optimal given the greedy choices. This keeps the stack as increasing as the "must keep" constraints allow, which gives the lexicographically smallest result.

import java.util.*;

public class RemoveDuplicateLetters {

    public static String removeDuplicateLetters(String s) {
        if (s == null || s.isEmpty()) return "";
        int[] last = new int[26];                       // last index of each letter
        for (int i = 0; i < s.length(); i++) last[s.charAt(i) - 'a'] = i;

        boolean[] inStack = new boolean[26];
        StringBuilder stack = new StringBuilder();      // StringBuilder used as a stack

        for (int i = 0; i < s.length(); i++) {
            char c = s.charAt(i);
            if (inStack[c - 'a']) continue;             // already placed optimally
            while (stack.length() > 0) {
                char top = stack.charAt(stack.length() - 1);
                if (top > c && last[top - 'a'] > i) {   // bigger AND can be re-added later
                    stack.deleteCharAt(stack.length() - 1);
                    inStack[top - 'a'] = false;
                } else break;
            }
            stack.append(c);
            inStack[c - 'a'] = true;
        }
        return stack.toString();
    }

    // Plain dedup (NOT lexicographically smallest), for contrast: keeps first occurrences
    static String simpleDedup(String s) {
        return s.chars().distinct().collect(StringBuilder::new, StringBuilder::appendCodePoint, StringBuilder::append).toString();
    }

    public static void main(String[] args) {
        System.out.println(removeDuplicateLetters("bcabc"));     // abc
        System.out.println(removeDuplicateLetters("cbacdcbc"));  // acdb
        System.out.println(removeDuplicateLetters("aaaa"));      // a
        System.out.println(removeDuplicateLetters("abacb"));     // abc
        System.out.println(simpleDedup("cbacdcbc"));             // cbad (different!)
    }
}

B40 Search in a rotated sorted array (4,5,6,7,0,1,2,3). TCS

Modified binary search, O(log n). At every step one half is sorted. If the target lies within that sorted half, search there; otherwise search the other half.

static int search(int[] a, int target) {
    int lo = 0, hi = a.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] == target) return mid;
        if (a[lo] <= a[mid]) {                          // left half sorted
            if (target >= a[lo] && target < a[mid]) hi = mid - 1; else lo = mid + 1;
        } else {                                        // right half sorted
            if (target > a[mid] && target <= a[hi]) lo = mid + 1; else hi = mid - 1;
        }
    }
    return -1;
}

Problem: an ascending array rotated at an unknown pivot, for example [4,5,6,7,0,1,2,3]. Find the index of a target in O(log n). No duplicates.

Key insight: at any mid, at least one half is sorted. Check which half is sorted by comparing nums[lo] with nums[mid]. If the target lies inside the sorted half's range, search there; otherwise search the other half.

public class RotatedSearch {

    public static int search(int[] nums, int target) {
        if (nums == null || nums.length == 0) return -1;
        int lo = 0, hi = nums.length - 1;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;                 // avoids int overflow of (lo+hi)
            if (nums[mid] == target) return mid;

            if (nums[lo] <= nums[mid]) {                  // left half [lo..mid] is sorted
                if (nums[lo] <= target && target < nums[mid]) hi = mid - 1;
                else lo = mid + 1;
            } else {                                      // right half [mid..hi] is sorted
                if (nums[mid] < target && target <= nums[hi]) lo = mid + 1;
                else hi = mid - 1;
            }
        }
        return -1;
    }

    // Bonus: index of the minimum element (= rotation count)
    public static int findPivot(int[] nums) {
        int lo = 0, hi = nums.length - 1;
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (nums[mid] > nums[hi]) lo = mid + 1;       // the minimum is to the right of mid
            else hi = mid;                                // the minimum is at mid or to its left
        }
        return lo;
    }

    public static void main(String[] args) {
        int[] nums = {4, 5, 6, 7, 0, 1, 2, 3};
        System.out.println(search(nums, 1));   // 5
        System.out.println(search(nums, 6));   // 2
        System.out.println(search(nums, 3));   // 7
        System.out.println(search(nums, 9));   // -1
        System.out.println(search(new int[]{1}, 1)); // 0
        System.out.println(search(new int[]{}, 1));  // -1
        System.out.println(findPivot(nums));   // 4 (value 0)
    }
}

static int binarySearch(int[] a, int key) {

        int mid = lo + (hi - lo) / 2;            // avoids int overflow

Explanations

  • Bubble Sort: repeatedly walk the array and swap adjacent elements that are out of order. After pass k, the k largest elements are in place at the end. With an early-exit flag (no swaps in a pass means sorted), the best case is O(n). It is only for teaching or tiny or nearly-sorted inputs.
  • Merge Sort: divide and conquer. Split in half, recursively sort each half, then merge two sorted halves in linear time. Always O(n log n), stable, needs O(n) auxiliary space. Good for linked lists and external (disk) sorting. Java's Collections.sort/Arrays.sort(Object[]) uses TimSort, a hybrid of merge sort and insertion sort.
  • Quick Sort: pick a pivot, partition so that elements smaller than the pivot go left and larger go right, then recurse on both sides. In place, very cache-friendly, average O(n log n). The worst case is O(n^2) when the pivot is always the smallest or largest (for example, sorted input with a first or last pivot). Mitigate with a random or median-of-three pivot. Not stable. Java's Arrays.sort(int[]) uses Dual-Pivot Quicksort, safe for primitives because stability does not matter for them.
  • Linear Search: check each element in turn. O(n), works on unsorted data and any equals.
  • Binary Search: on sorted data, compare with the middle and discard half each step. O(log n). Java provides Arrays.binarySearch/Collections.binarySearch, which return -(insertionPoint) - 1 when the key is not found.
import java.util.*;

public class SortingAndSearching {

    // ---------- Bubble Sort ----------
    static void bubbleSort(int[] a) {
        int n = a.length;
        for (int pass = 0; pass < n - 1; pass++) {
            boolean swapped = false;
            for (int j = 0; j < n - 1 - pass; j++) {     // the last `pass` elements are already in place
                if (a[j] > a[j + 1]) {
                    int t = a[j]; a[j] = a[j + 1]; a[j + 1] = t;
                    swapped = true;
                }
            }
            if (!swapped) break;                         // already sorted: best case O(n)
        }
    }

    // ---------- Merge Sort ----------
    static void mergeSort(int[] a) {
        if (a == null || a.length < 2) return;
        int[] tmp = new int[a.length];                   // allocate the buffer once
        mergeSort(a, tmp, 0, a.length - 1);
    }

    private static void mergeSort(int[] a, int[] tmp, int lo, int hi) {
        if (lo >= hi) return;
        int mid = lo + (hi - lo) / 2;
        mergeSort(a, tmp, lo, mid);
        mergeSort(a, tmp, mid + 1, hi);
        if (a[mid] <= a[mid + 1]) return;                // optimisation: already in order
        merge(a, tmp, lo, mid, hi);
    }

    private static void merge(int[] a, int[] tmp, int lo, int mid, int hi) {
        System.arraycopy(a, lo, tmp, lo, hi - lo + 1);
        int i = lo, j = mid + 1, k = lo;
        while (i <= mid && j <= hi) {
            a[k++] = (tmp[i] <= tmp[j]) ? tmp[i++] : tmp[j++];   // <= keeps it STABLE
        }
        while (i <= mid) a[k++] = tmp[i++];
        while (j <= hi) a[k++] = tmp[j++];                    // usually already in place; kept for clarity
    }

    // ---------- Quick Sort (Lomuto partition, random pivot) ----------
    private static final Random RND = new Random();

    static void quickSort(int[] a) {
        if (a == null) return;
        quickSort(a, 0, a.length - 1);
    }

    private static void quickSort(int[] a, int lo, int hi) {
        while (lo < hi) {
            int p = partition(a, lo, hi);
            // Recurse into the smaller side and loop on the larger: O(log n) stack depth
            if (p - lo < hi - p) { quickSort(a, lo, p - 1); lo = p + 1; }
            else                 { quickSort(a, p + 1, hi); hi = p - 1; }
        }
    }

    private static int partition(int[] a, int lo, int hi) {
        int r = lo + RND.nextInt(hi - lo + 1);           // random pivot avoids O(n^2) on sorted input
        swap(a, r, hi);
        int pivot = a[hi];
        int i = lo;                                      // a[lo..i-1] < pivot
        for (int j = lo; j < hi; j++) {
            if (a[j] < pivot) swap(a, i++, j);
        }
        swap(a, i, hi);                                  // the pivot goes to its final position
        return i;
    }

    private static void swap(int[] a, int i, int j) { int t = a[i]; a[i] = a[j]; a[j] = t; }

    // ---------- Linear Search ----------
    static int linearSearch(int[] a, int key) {
        for (int i = 0; i < a.length; i++) if (a[i] == key) return i;
        return -1;
    }

    // ---------- Binary Search (iterative) ----------
    static int binarySearch(int[] a, int key) {
        int lo = 0, hi = a.length - 1;
        while (lo <= hi) {
            int mid = (lo + hi) >>> 1;                   // overflow-safe
            if (a[mid] == key) return mid;
            if (a[mid] < key) lo = mid + 1;
            else hi = mid - 1;
        }
        return -1;
    }

    // Binary Search (recursive)
    static int binarySearchRec(int[] a, int key, int lo, int hi) {
        if (lo > hi) return -1;
        int mid = (lo + hi) >>> 1;
        if (a[mid] == key) return mid;
        return a[mid] < key ? binarySearchRec(a, key, mid + 1, hi) : binarySearchRec(a, key, lo, mid - 1);
    }

    // Variant: first occurrence when duplicates exist (lower bound)
    static int firstOccurrence(int[] a, int key) {
        int lo = 0, hi = a.length - 1, ans = -1;
        while (lo <= hi) {
            int mid = (lo + hi) >>> 1;
            if (a[mid] >= key) { if (a[mid] == key) ans = mid; hi = mid - 1; }
            else lo = mid + 1;
        }
        return ans;
    }

    public static void main(String[] args) {
        int[] data = {38, 27, 43, 3, 9, 82, 10, 3};

        int[] b = data.clone(); bubbleSort(b);
        int[] m = data.clone(); mergeSort(m);
        int[] q = data.clone(); quickSort(q);
        System.out.println("Bubble: " + Arrays.toString(b));  // [3, 3, 9, 10, 27, 38, 43, 82]
        System.out.println("Merge : " + Arrays.toString(m));  // [3, 3, 9, 10, 27, 38, 43, 82]
        System.out.println("Quick : " + Arrays.toString(q));  // [3, 3, 9, 10, 27, 38, 43, 82]

        System.out.println("Linear search 82 in unsorted: " + linearSearch(data, 82));   // 5
        System.out.println("Binary search 27: " + binarySearch(m, 27));                  // 4
        System.out.println("Binary search rec 43: " + binarySearchRec(m, 43, 0, m.length - 1)); // 6
        System.out.println("Binary search 100: " + binarySearch(m, 100));                // -1
        System.out.println("First occurrence of 3: " + firstOccurrence(m, 3));           // 0
        System.out.println("JDK binarySearch 11: " + Arrays.binarySearch(m, 11));        // -5 (insertion point 4)

        // Edge cases
        int[] empty = {}; quickSort(empty); mergeSort(empty); bubbleSort(empty);
        System.out.println(Arrays.toString(empty) + " " + binarySearch(empty, 1));       // [] -1

        // Large sanity check against Arrays.sort
        int[] big = new Random(42).ints(100_000, -1000, 1000).toArray();
        int[] expected = big.clone(); Arrays.sort(expected);
        int[] m2 = big.clone(); mergeSort(m2);
        int[] q2 = big.clone(); quickSort(q2);
        System.out.println(Arrays.equals(expected, m2) && Arrays.equals(expected, q2));  // true
    }
}

What the JDK uses:

  • Arrays.sort(int[]/long[]/double[]...): Dual-Pivot Quicksort (Yaroslavskiy), with insertion sort for small ranges. Not stable, but primitives do not need stability.
  • Arrays.sort(Object[]), List.sort, Collections.sort: TimSort. Stable, O(n) on already-sorted runs, and needs a consistent comparator, otherwise "Comparison method violates its general contract!".
  • Arrays.parallelSort: parallel merge sort over the ForkJoin pool for large arrays.

Gotchas: binary search on unsorted data returns garbage rather than throwing. Quicksort with a fixed pivot on sorted input degrades to O(n^2) and can cause a StackOverflowError on large n. Merge sort's <= (instead of <) is what makes it stable.

Likely follow-ups:

  • Why does Java use different algorithms for primitives and objects? Objects need stability (sorting by one key must keep a previous ordering), and TimSort is fast on real-world partially sorted data. Primitives cannot be told apart when equal, so the faster unstable quicksort is fine.
  • Which sort for a linked list? Merge sort: O(1) extra space with pointer manipulation, and no random access is needed.
  • What makes quicksort's worst case O(n^2) and how do you avoid it? Consistently bad pivots (already sorted input with a first or last pivot). Use a random or median-of-three pivot, or introsort (fall back to heapsort when recursion gets deep).
  • Other O(n) sorts? Counting sort, radix sort, and bucket sort, for integer keys in a bounded range. They are non-comparison sorts.

Split the text into words, normalise them (lowercase, strip punctuation), then group by the word and count. Use LinkedHashMap if the output should keep first-occurrence order.

import java.util.*;
import java.util.function.Function;
import java.util.stream.*;

public class WordFrequency {
    static Map<String, Long> frequency(String text) {
        if (text == null || text.isBlank()) return Map.of();
        return Arrays.stream(text.toLowerCase().split("\\W+"))   // \W+ also drops punctuation
                .filter(w -> !w.isEmpty())                        // leading punctuation gives ""
                .collect(Collectors.groupingBy(Function.identity(), LinkedHashMap::new, Collectors.counting()));
    }

    // Loop version with Map.merge
    static Map<String, Integer> frequencyLoop(String text) {
        Map<String, Integer> counts = new LinkedHashMap<>();
        for (String w : text.toLowerCase().split("\\W+")) {
            if (!w.isEmpty()) counts.merge(w, 1, Integer::sum);
        }
        return counts;
    }

    public static void main(String[] args) {
        String s = "The cat and the hat. The CAT sat!";
        System.out.println(frequency(s));
        System.out.println(frequencyLoop(s));

        // Top 2 most frequent words
        List<String> top = frequency(s).entrySet().stream()
                .sorted(Map.Entry.<String, Long>comparingByValue().reversed())
                .limit(2).map(Map.Entry::getKey).toList();
        System.out.println(top);
    }
}
// Output:
// {the=3, cat=2, and=1, hat=1, sat=1}
// {the=3, cat=2, and=1, hat=1, sat=1}
// [the, cat]

Points to mention

  • split("\\s+") keeps punctuation attached ("hat." ≠ "hat"); split("\\W+") splits on anything that isn't a letter, digit or underscore. For non-English text use split("[^\\p{L}\\p{N}]+").
  • A leading separator produces an empty first token, hence the filter.
  • Complexity: O(n) time over the characters, O(k) space for k distinct words.
  • Use TreeMap::new for alphabetical output, or HashMap (the default) when order doesn't matter.

Likely follow-ups:

  • Why Collectors.counting() returns Long? It's defined as summingLong(e -> 1L); use summingInt(w -> 1) for Integer.
  • Very large file? Stream it with Files.lines(path) and flatMap(line -> Arrays.stream(line.split("\\W+"))) so the whole file is never in memory (B32).
  • Case-sensitive count? Drop the toLowerCase().

Decide first whether the result should be sorted or keep insertion order, and whether the inputs are already sorted. Each case has a natural solution.

import java.util.*;
import java.util.stream.*;

public class MergeWithoutDuplicates {
    // 1. Sorted result: concat + distinct + sorted, O((n+m) log(n+m))
    static int[] mergeSorted(int[] a, int[] b) {
        return IntStream.concat(Arrays.stream(a), Arrays.stream(b)).distinct().sorted().toArray();
    }

    // 2. Keep first-occurrence order: LinkedHashSet, O(n+m)
    static List<Integer> mergeKeepOrder(int[] a, int[] b) {
        Set<Integer> set = new LinkedHashSet<>();
        for (int x : a) set.add(x);
        for (int x : b) set.add(x);
        return new ArrayList<>(set);
    }

    // 3. Inputs already sorted: two-pointer merge with dedupe, O(n+m), no hashing
    static int[] mergeTwoPointer(int[] a, int[] b) {
        int[] out = new int[a.length + b.length];
        int i = 0, j = 0, k = 0;
        while (i < a.length || j < b.length) {
            int next;
            if (j >= b.length || (i < a.length && a[i] <= b[j])) next = a[i++];
            else next = b[j++];
            if (k == 0 || out[k - 1] != next) out[k++] = next;   // skip duplicates
        }
        return Arrays.copyOf(out, k);
    }

    public static void main(String[] args) {
        int[] a = {1, 2, 3, 4}, b = {3, 4, 5, 6};
        System.out.println(Arrays.toString(mergeSorted(a, b)));
        System.out.println(mergeKeepOrder(new int[]{5, 1, 5}, new int[]{2, 1, 9}));
        System.out.println(Arrays.toString(mergeTwoPointer(new int[]{1, 1, 3}, new int[]{1, 2, 3, 7})));
    }
}
// Output:
// [1, 2, 3, 4, 5, 6]
// [5, 1, 2, 9]
// [1, 2, 3, 7]
Approach Time Extra space Output order
concat().distinct().sorted() O((n+m) log(n+m)) O(n+m) ascending
LinkedHashSet O(n+m) average O(n+m) first occurrence
Two-pointer (sorted inputs) O(n+m) O(n+m) output only ascending

Edge cases: empty arrays (all three handle them), duplicates inside one array (also removed), null arrays (validate first). For Integer[] or objects, use Stream.concat(Arrays.stream(a), Arrays.stream(b)).distinct(), which relies on equals/hashCode.

Likely follow-ups:

  • Keep duplicates but merge sorted? Drop the out[k - 1] != next check: that's the merge step of merge sort (B41).
  • Intersection instead of union? Set<Integer> s = toSet(a); s.retainAll(toSet(b));
  • Why is distinct() O(n)? It tracks seen elements in a HashSet internally (stateful intermediate operation).
B44 Rotate an N × N matrix by K × 90° clockwise. Other rounds (Question List)
  • First normalise K with k = ((K % 4) + 4) % 4. Four rotations bring the matrix back to where it started, and this formula also handles negative K (a counter-clockwise rotation).
  • One 90° clockwise rotation, in place: transpose, then reverse each row. Repeat this k times.
  • Each rotation is O(n²) time and O(1) extra space. A 180° rotation can be done in one step by reversing the order of the rows and then reversing each row.
import java.util.Arrays;

public class RotateMatrix {
    static void rotate90(int[][] m) {
        int n = m.length;
        for (int i = 0; i < n; i++)
            for (int j = i + 1; j < n; j++) { int t = m[i][j]; m[i][j] = m[j][i]; m[j][i] = t; }
        for (int[] row : m)
            for (int l = 0, r = n - 1; l < r; l++, r--) { int t = row[l]; row[l] = row[r]; row[r] = t; }
    }

    static void rotate(int[][] m, int K) {
        int k = ((K % 4) + 4) % 4;
        for (int i = 0; i < k; i++) rotate90(m);
    }

    public static void main(String[] args) {
        int[][] m = {{1, 2, 3}, {4, 5, 6}, {7, 8, 9}};
        rotate(m, 1);
        for (int[] row : m) System.out.println(Arrays.toString(row));
    }
}
// Output:
// [7, 4, 1]
// [8, 5, 2]
// [9, 6, 3]

Rotating four times brings the matrix back, so only K mod 4 matters. Normalise with k = ((K % 4) + 4) % 4 so that negative K (counter-clockwise) also works: K = -1 becomes 3 clockwise turns.

One 90° clockwise turn, in place: transpose (swap m[i][j] with m[j][i]), then reverse each row.

import java.util.Arrays;

public class RotateMatrix {
    static void rotate(int[][] m, int K) {
        int k = ((K % 4) + 4) % 4;
        for (int r = 0; r < k; r++) rotate90(m);
    }

    static void rotate90(int[][] m) {
        int n = m.length;
        for (int i = 0; i < n; i++)                 // 1. transpose
            for (int j = i + 1; j < n; j++) {
                int t = m[i][j]; m[i][j] = m[j][i]; m[j][i] = t;
            }
        for (int[] row : m)                         // 2. reverse each row
            for (int l = 0, h = n - 1; l < h; l++, h--) {
                int t = row[l]; row[l] = row[h]; row[h] = t;
            }
    }

    static int[][] sample() { return new int[][]{{1, 2, 3}, {4, 5, 6}, {7, 8, 9}}; }

    public static void main(String[] args) {
        for (int K : new int[]{1, 2, 3, -1}) {
            int[][] m = sample();
            rotate(m, K);
            System.out.println("K=" + K + " " + Arrays.deepToString(m));
        }
    }
}
// Output:
// K=1 [[7, 4, 1], [8, 5, 2], [9, 6, 3]]
// K=2 [[9, 8, 7], [6, 5, 4], [3, 2, 1]]
// K=3 [[3, 6, 9], [2, 5, 8], [1, 4, 7]]
// K=-1 [[3, 6, 9], [2, 5, 8], [1, 4, 7]]

Shortcuts

  • 180°: reverse the order of the rows, then reverse each row; no transpose needed.
  • 270° clockwise (90° counter-clockwise): transpose, then reverse the order of the rows.
  • Layer by layer: for each ring, rotate four elements at a time (top ← left ← bottom ← right ← top). Same O(n²) in a single pass, but easier to get indices wrong in an interview.

Complexity: O(n²) time per 90° turn, at most 3 turns after normalising, so O(n²) overall; O(1) extra space.

Non-square matrices can't be rotated in place: allocate int[cols][rows] and set out[j][rows - 1 - i] = m[i][j].

Likely follow-ups:

  • Why does transpose + reverse work? Transposing maps (i, j) → (j, i); reversing a row maps (j, i) → (j, n−1−i), which is exactly the 90° clockwise mapping.
  • Very large K like 10⁹? Still just K % 4 turns.
  • Rotate an image buffer? Same index mapping, usually into a new array.
B45 Check whether brackets (), {}, [] are balanced. G2
  • Use a stack (ArrayDeque). Push every opening bracket. On a closing bracket, pop and check that it matches. If the stack is empty or the bracket does not match, return false.
  • At the end the stack must be empty. That catches unclosed brackets like "((".
  • The stack is what makes brackets close in reverse order, so "([)]" fails.
  • O(n) time, O(n) space.
import java.util.*;

public class BalancedBrackets {
    static boolean isBalanced(String s) {
        Deque<Character> stack = new ArrayDeque<>();
        for (char c : s.toCharArray()) {
            switch (c) {
                case '(', '{', '[' -> stack.push(c);
                case ')', '}', ']' -> {
                    if (stack.isEmpty()) return false;
                    char open = stack.pop();
                    if ((c == ')' && open != '(') || (c == '}' && open != '{') || (c == ']' && open != '[')) return false;
                }
                default -> { }
            }
        }
        return stack.isEmpty();
    }

    public static void main(String[] args) {
        System.out.println(isBalanced("{[()]}"));
        System.out.println(isBalanced("([)]"));
        System.out.println(isBalanced("(("));
    }
}
// Output:
// true
// false
// false

Use a stack. Push every opening bracket. On a closing bracket, the top of the stack must be its matching opener: pop it, otherwise the string is unbalanced. At the end the stack must be empty. A stack fits because brackets close in last-opened, first-closed (LIFO) order: if two brackets are open, the inner one has to close first.

import java.util.*;

public class BalancedBrackets {
    private static final Map<Character, Character> PAIRS = Map.of(')', '(', ']', '[', '}', '{');

    static boolean isBalanced(String s) {
        Deque<Character> stack = new ArrayDeque<>();
        for (char c : s.toCharArray()) {
            if (PAIRS.containsValue(c)) stack.push(c);                 // opener
            else if (PAIRS.containsKey(c)) {                            // closer
                if (stack.isEmpty() || stack.pop() != PAIRS.get(c)) return false;
            }                                                           // other chars ignored
        }
        return stack.isEmpty();                                         // leftover openers -> false
    }

    public static void main(String[] args) {
        for (String s : List.of("{[()]}", "([)]", "((", "", "a(b)c[d]", "}"))
            System.out.println("\"" + s + "\" -> " + isBalanced(s));
    }
}
// Output:
// "{[()]}" -> true
// "([)]" -> false
// "((" -> false
// "" -> true
// "a(b)c[d]" -> true
// "}" -> false
